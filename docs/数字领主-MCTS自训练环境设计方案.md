# 数字领主·MCTS 自训练环境设计方案（共识 v1）

> **用途**：记录训练环境与 MCTS AI 设计讨论达成的全部共识，作为实现的直接依据。
> **版本**：v1.3（2026-09-20）。§2.2 加点阶段决策规则已定稿（M=1）；§10 实施顺序已定稿；§9 增补同结构对局日志；线上接入待训练达标后另立项。
> **与旧方案的关系**：本方案为独立重新设计，**不沿用** docs 下旧 MCTS 系列（《数字领主-MCTS-AI训练方案.md》、局面评估设计 v2/v3）的任何结论。

---

## 1. 目标与总体定位（%1 / %2）

- **目标**：训练出一个 MCTS 数字领主 AI；训练基准为"不调参的 MCTS"（同引擎、种子权重固定、argmax 决策）。验收标准：对基准胜率 ≥ 60%（100 局）。
- **形态**：**纯搜索型 MCTS，无神经网络**；局面评估为含参的手工特征线性加权函数 E_te，权重通过自对弈数据训练。
- **适用范围**：**严格 1v1**（唯一对手、无队友）；多人/队伍模式不在训练范围内。
- **训练范式要点**：
  - 结果监督式：E_te 拟合"局面 → 终局胜负"；
  - **回合级决策单元**：MCTS 树节点落在回合边界，动作 = 完整回合计划——评估点语义统一（无行动/加点阶段边界突变）、信用链缩短；
  - 战略循环对齐：第 N 回合加点制造威胁 → 对手回合回应 → 第 N+1 回合执行兑现；**叶评估点 = 根势力第二个回合结束时**（收益已兑现、对手尚未反制）；
  - 对手建模放进搜索（对抗搜索，对手节点取 min），不放进评估函数；
  - 训练用 self-play（双方同权重 + 温度采样），避免对固定对手特攻；固定基准只做验收，不进训练目标。

## 2. 候选计划生成

### 2.1 行动阶段（%9）：按《数字领主-行动阶段决策规则.md》v1.5 原样实现

三段式结构：**前置行为 → 基础行为段 → 防守行为段**，输出 **top-4 候选执行方案**（训练环境将 v1.5 的 top-3 调整为 top-4：M=1 后以行动路径数补偿候选多样性）。

| 段 | 要点 |
|---|---|
| 前置行为 | 进攻据点；行动阶段开始时判定一次；成立条件 = Σ 进攻力 > 据点防守兵力；S 内兵按兵力降序依次 ATTACK；**必须作为最终方案前缀** |
| 基础行为段 | 5 种基础行为（铺场 / 就近进攻 / 远海进攻 / 自杀 / 兑换）；DFS 枚举行为链；规则 1 锁兵延续、规则 2 链终止分派（普通终止 / 自杀消耗战循环 / 兑换分支）；**原点级剪枝**：存在自杀或兑换行为时仅保留该二类分支（不应用于规则 1 锁兵状态）；每原点取 top-2 备选链递归展开 |
| 防守行为段 | 对每条候选路径：基线 = 该路径方案 E_ape；对每个有移动力的兵尝试下海（距离 1 空海洋格，单意图，一步入海即止）；**批准所有使 E_ape 相对基线增加的下海**（各兵独立判定）；冲突（目标格相同）意图全部排除；防守意图附于基础行为之后 |

- 最终方案 = 前置链（若成立）+ 基础行为意图序列 + 防守意图列表。
- E_ape 在该算法中的调用点：链终止剪枝打分、叶子原点方案打分、防守基线与批准判定；**双快照基准统一为行动阶段开始时的局面**。

### 2.2 加点阶段（%10）：唯一方案（M=1，2026-09-20 定稿）

优先级顺序：**规则 1（防断电）→ 规则 2（防击杀）→ 规则 3（E_te 引导饱和分配）**；前两级消耗后的剩余点数进入规则 3。

**规则 1（防断电）**
- 对象：单个兵被吃即引发断电级联的**割点型连兵**；
- 威胁值：**能移动到该兵周围**的敌兵中进攻力的最大值（可达语义；实现复用战场消耗 BFS——敌方连兵多步推进、断兵一步，目标 = 被威胁兵的邻格集合，进攻力按抵达后兵力结算）；
- 阈值：按敌方**当前兵力**计算，**不计**敌方下回合加点潜力（军备竞赛式防守，省点留给饱和攻击）；
- 防御量 = 使该兵兵力 > 威胁进攻力所需点数；**全有或全无**——剩余点数不足则整兵跳过（进攻成败是二值的，部分防御 = 纯浪费）。

**规则 2（防击杀）**
- 对象：邻格有敌兵的我方连兵；威胁值 = **邻格**敌兵进攻力最大值（与规则 1 的可达语义刻意不对称：割点防可达威胁、普通连兵只防已贴脸威胁）；
- 阈值与全有或全无同规则 1；
- 多兵依次尝试，全局排序 =（是否割点、断电规模降序）——即规则 1 对象先于规则 2。

**规则 3（E_te 引导的饱和分配，2026-09-20 修订）**
- 对**每个**连兵：**模拟加当前全部剩余点数**（ADD_POINT 只加兵力、无级联事件，模拟后撤回）→ 计算模拟后局面的 E_te（回合末 = 模拟后局面）；
- 取 E_te 值最高的**前 3**为"无限加点池"，按 E_te 值排序；
- 剩余点数**逐点抽签**分配：
  - 池内兵：按排名赋予**线性递增权重**（排名越前、被抽中概率越高）；
  - 池外兵：权重固定 1，**合计最多获得总加点的 15%（向下取整）**；
- 随机源 = **局面哈希做种子**（同局面同分配，保证 MCTS 树内候选一致；不同局面分布不同）；
- 无任何连兵时直接 SWITCH_PHASE 交还点数。
- **前中期加点限制（2026-09-20 修订）**：回合数 < T 时，只允许在**周围（距离 1）有空据点/空平原**的连兵上加点（规则 1/2 候选与规则 3 候选集均按此过滤）；回合数 ≥ T 恢复全部连兵可加点；规则优先级与分配机制不变。
- **后期直接可达限制（2026-09-20 修订）**：回合数 ≥ T 时，**无法直接到达敌方**的连兵不能进入规则 3 加点池——"无法直接到达" = 无论怎么走都会先遇到 2 次友兵（遇到 1 次友兵仍算可到达；路径途中不遇友兵/遇 1 次友兵到达敌方兵即视为可到达；起点自身不计）。

**性能预案**：规则 3 的逐兵 E_te 探测 = 每节点 4 行动方案 × |连兵| 次 E_te 调用（E_te 含特征 3/4 的 BFS/断连模拟，为全系统最贵函数）；先按全精度实现 + profile，过慢则排序改用**去掉特征 3/4 的轻量 E_te 变体**（排序用途不需要全精度）。

### 2.3 候选组合

- MCTS 每节点动作空间 = **4 条行动方案（top-4）× 1 种加点方案 = 4 个候选回合计划**；双方对称使用同一生成器（对手节点同样生成对手的候选）。
- 加点方案在每个行动候选的**行动后局面**上独立运行——4 个行动候选各自产出自己的加点序列，构成完整回合计划。
- **无随机化**（加点方案内部的"随机抽签"以局面哈希为种子，同局面结果确定）；早期讨论的"手写战术模板库 + 全局优先级级联 + 实例化变体 + K=10 截断"契约**作废**。

## 3. 评估函数

### 3.1 E_te（回合结束评价，训练对象，%4）

- **形式**：`E_te = Σ wᵢ·fᵢ`，线性加权；**双快照输入** `E_te(回合结束局面, 该回合开始局面)`。
- **中盘/残局双权重**：`T = ⌈log₂(地图长×地图宽/100)⌉ + 5`（向上取整）；回合数 < T 用中盘权重，≥ T 用残局权重；两套权重独立训练、**初值相同**（= 种子权重）。
- **种子权重**（= 冷启动初值 = 基准的固定权重）：

| # | 特征 | 定义 | 种子权重 |
|---|---|---|---|
| 1 | 子力差值 | 我总兵力 − sqrt(敌总兵力 × (敌总兵力 + 敌连兵数))；单快照可算 | +0.05 |
| 2 | 连兵差值 | (回合末我连兵 − 敌连兵) − (回合初我连兵 − 敌连兵)；双快照 | +2.0 |
| 3 | 网络脆弱性 | 见下述算法 | −1.0 |
| 4 | 网络可靠性 | 见下述算法 | −0.5 |
| 5 | 我方威胁性 | 见下述算法（2026-09-20 重定义） | 前期 50.0 / 残局 2.0 |
| 6 | 叫杀得分 | 布尔 | +100 |

**特征 3（网络脆弱性）**——当前连兵结构面对真实敌方时可被破坏的最大程度：
1. 对敌兵做战场 BFS（消耗 = 目标格我方兵力 + 1），得敌方可达网络；
2. 取网络内所有我方兵，剪枝到**边界兵**（周围有不在该网络内的友兵者）；
3. 边界兵做组合（**组合上限 4**），每个组合模拟敌方吃掉这些兵，值 = 我方连兵数减少量（被吃的连兵 + 断电脱离网络的连兵）；
4. 取组合最大值。敌方连兵可多步推进，**敌方断兵只能进攻一次**。

**特征 4（网络可靠性）**——连兵网络对敌方单兵进攻的性价比：
1. 取敌方距我方兵最近的前 **N=4** 个兵（**不含断兵**），各建子局面；
2. 每个子局面给该兵增加"敌方当前连兵数"的兵力（模拟敌方下回合集中加点）；
3. 该强化敌兵发起**单兵连续进攻链**（连兵进攻后移动力仍在）：反复吃下一个目标（消耗 = 目标兵力 + 1，反击照常结算），直到兵力不足以再吃或无可吃目标；
4. 值 = 连兵减少数量²（被吃连兵 + 断电连兵）/ 该敌兵因进攻损失的总兵力；取 4 个子局面的最大值。

**特征 5（我方威胁性，2026-09-20 重定义）**：对每个我方兵计算到敌方据点的距离 d——d = 假设该兵兵力 1000、**不考虑敌方任何兵**（敌兵格按空格计）走到最近敌方据点**周围（距离 1）**时的兵力下降值（每步消耗 1；阻挡兵/山地/虚空不可通过）；特征值 = Σ (4·(地图长+地图宽) − d) × 该兵兵力，不可达按 d = 4·(长+宽) 计（贡献 0）。前期初始权重 50.0、残局 2.0（训练对象）。

**特征 6（叫杀得分）**：我方有兵处于敌方据点周围（距离 1），且敌方下回合可加点总数（= 敌方当前连兵数）**小于**该兵兵力 → 触发，给予固定大量奖励（布尔，种子权重 100）。

**战场 BFS 通用规则**：连兵可多步推进；推进到有兵格的消耗 = 该格防守方兵力 + 1，空格 = 1。

### 3.2 E_ape（行动阶段排序工具，权重固定不训练，%7）

- **角色**：纯排序工具（§2.1 算法的剪枝/方案/防守打分）；**搜索的价值回传只用 E_te**，E_ape 不进入搜索评价。
- **双快照输入**（行动后/链终止局面 vs 行动阶段开始局面）；前期/残局切换沿用 E_te 的阈值 T。

| # | 特征 | 定义 | 前期 | 残局 |
|---|---|---|---|---|
| 1 | 兵力差净变化 | (行动后我 − 敌总兵力) − (回合初我 − 敌总兵力) | 1.0 | 1.0 |
| 2 | 可靠连兵差净变化 | (行动后我有效连兵 − 敌连兵) − (回合初我连兵 − 敌连兵) | 1.0 | 1.0 |
| 3 | 我方坏型数 | Σ 割点型连兵 × max(0, 1 − 0.2x) | 0 | −3.0 |
| 4 | 我方威胁程度 | 2 − d/B，d = min(我方兵 × 敌方据点的 hexDistance) | +5.0 | +0.3 |

- **特征 2 威胁排除**：我方连兵中"周围有 ≥ 2 个威胁性敌兵"者不计入有效连兵；威胁性敌兵 = **兵力 ≥ 2 的敌方连兵 ∪ 任意敌方断兵**。**排除仅在行动后快照执行**（回合初用原始连兵数）；敌方连兵数不做排除。
- **特征 3 坏型与防护衰减**：坏型 = "去除该兵即导致部分区域断电（脱离据点变断兵）"的我方连兵（割点），同样排除威胁包围者；每个坏型的贡献乘以 `max(0, 1 − 0.2x)`，x 由**防护 BFS** 给出：
  - 从坏型出发：**不可通过** = 我方连兵、阻挡兵、山地/虚空；**代价 +1** = 我方断兵、野生兵；**代价 0** = 空格、海洋、敌方非据点兵（无视敌方所有兵）；
  - 目标 = 地形为据点且驻有敌方兵的格；x = 最小总代价（0-1 BFS 实现）。

## 4. MCTS 搜索引擎（%5）

| 项 | 决策 |
|---|---|
| 树结构 | 回合级树：节点 = 回合边界，动作 = 候选回合计划（§2.3，4 个） |
| 深度 | **根势力 2 回合 + 对方 1 回合（3 层）**；叶 = 根势力第二个回合结束时；对手决策时对称（对手为根的 3 层树） |
| 对抗语义 | 1v1、唯一对手；对手节点取 min；价值始终以根视角存储与回传 |
| 选择策略 | UCB1，探索常数 **c = 1.0**（基准与训练 AI 共用） |
| 搜索预算 | 每决策固定 **300 次模拟**，训练与实战一致 |
| 树复用 | **不复用**，每决策从零建树 |
| 评估缓存 | 叶评估按局面哈希缓存（特征 3/4 的 BFS / 断连模拟同局面只算一次） |

## 5. 自对弈与训练循环（%6 / %11）

| 项 | 决策 |
|---|---|
| 自对弈 | 双方 = 当前权重 + 同一 MCTS 引擎；根节点**温度采样**（按访问比例采样而非 argmax）产生对局多样性 |
| τ 衰减 | 0 → **500 局**线性 1.0 → 0.1，之后恒为 0.1；局内不区分阶段 |
| 拟合节奏 | **每 100 局**拟合一次；滑动窗口保留**最近 500 局** |
| 样本 | **全量收集**：对局中每个势力每个回合结束收集一份 =（双快照，当前回合数，终局状态）；**双视角对称**收集（各势力以自己为根视角）；标签 = 该势力终局结果：胜 +1 / 负 −1 / 平 0（超时算平） |
| 拟合算法 | **跨局 pairwise 排序学习**为主（胜局样本对 > 败局样本对；允许不单调）；**平方反比衰减**加权（w = 1/d²，d = 距终局的回合数）；次梯度/SGD，纯 TS 实现 |
| 对局上限 | **60 回合 或 1000 步**（步 = 双方累计提交的意图条数），任一到达即判平局 |
| 验收 | 训练后 AI argmax vs 基准 argmax（唯一差异 = E_te 权重）；**每 500 局抽检一次、每次 100 局、胜率 ≥ 60% 达标**；胜率不再上升可提前停 |

## 6. 训练环境工程形态（%11）

- **独立 Node/TS 训练程序**（`train/` 目录）：内存中直接 import `@dl/shared` 的 `initState` / `applyIntent` 跑对局；**不经**服务器、WS、bot 子进程、计时器、共识机制。
- **主进程 + worker 并行**：对局之间天然可并行；主进程维护权重与训练进度，收满 100 局做一次拟合并下发新权重（τ 按批次计算下发）；worker 数可配（默认按 CPU 核数），**先用单 worker 验证正确性**。
- **数据与产物**：训练样本 JSONL（特征向量 + 标签 + 元数据）；权重 JSON 持久化、版本可追溯；胜率曲线落盘。
- **拟合实现**：纯 TS（次梯度/SGD）；样本为 7 维特征（6 特征 + 回合数）+ 标签，规模无需 Python。

## 7. 地图（%8）

| 项 | 决策 |
|---|---|
| 训练图池 | 训练前**一次性生成 100 张**；复用 mapeditor 随机生成器 `mode='plain'`（均衡，权重 [0.58, 0.02, 0.16, 0.24, 0]，保证可走格连通）；**row ∈ [9,15]、column ∈ [11,17]** 每张随机；playerNum = 2；生成**不种子化**；**敌我初始据点必须能通过平原/据点连通**（仅经 PLAIN/CITY 地形；海洋不参与），不满足则重新生成直至 100 张满足（2026-09-20 新增检查） |
| 后手补偿 | 生成后将**先手（seat 1）据点兵力 = 3、后手（seat 2）据点兵力 = 4**（替换默认 DEFAULT_STRENGTH=5） |
| 取图方式 | **轮转**（按序循环），保证每个拟合批次（100 局）内 100 张图各出现一次 |
| 验收图池 | 用户单独设计的图；**预留文件夹 `train/eval-maps/`** 供用户放置；与训练图池无交集（泛化检验） |

## 8. 交付（%12）

- **先离线**：训练环境闭环 + 验收达标；产物 = 引擎代码 + 训练权重 + 评估报告（胜率曲线）。
- **线上接入另行设计**（`planAiTurn` 难度语义、ai-bot 子进程算力预算等），训练达标后单独立项。

## 9. 实现默认项（未逐条讨论，按以下默认实现，如有异议提出修改）

1. 拟合加**指向种子权重的轻量 L2 正则**（防权重漂移/发散）；收敛判据用验证集排序损失。
2. 特征值**不做归一化**（种子权重已在量级上做了平衡）。
3. 战场 BFS（E_te 特征 3/5）中**中立兵**处理与 E_ape 防护 BFS 一致：野生 = 可通过、消耗 +1；阻挡 = 不可通过。
4. **训练对局的势力构造**：双方 `isAI = false`（普通势力）**且 `playerId` 为非空虚拟 ID**（如 900001/900002）——`playerId=null && isAI=false` 会被 `initState` 按"无主势力"删光兵力（reducer §6.4）；虚拟 ID 同时充当日志 `from` 字段来源。由训练驱动器为双方生成意图——绕开 reducer"无存活人类势力即终局/停轮转"的 M4 扩展机制；胜负照常由规则引擎判定。
5. **对局日志与线上同结构**：每局写 `.jsonl`——首行 `GAME_START`（map / seatAssignments / spawnAssignments / seed / timeSettings 占位 / reducerVersion）、每条意图一行 `INTENT_BROADCAST`（from / fromSeat / intent / eventId 从 1 递增）、收尾 `GAME_OVER`（winners / winningTeam / forces / refId='end'），字段与 `backend/src/game/manager.ts` 落盘格式一致；`roomId` 用虚拟值。现有重放逻辑（如 ai-bot 的日志重建，只认 GAME_START / INTENT_BROADCAST / GAME_OVER 三类）可直接读取训练对局，抽查/渲染脚本按同一格式编写。
6. 温度采样与对局 seed：训练对局随机源不种子化（与地图生成一致）；`initState` 的 seed 字段填每局唯一值即可。
7. MCTS 回传：价值根视角存储，对手节点用翻转后的 UCB 取 min（标准对抗 MCTS 惯例）。

## 10. 实施顺序（%13，2026-09-20 定稿）

依赖链：**评估层（E_te/E_ape 及共享设施）→ 候选生成器（行动 + 加点）→ MCTS → 自对弈 / 拟合 / 验收**。每阶段以确定性单测收口，最后才进入训练动态。

| 阶段 | 内容 | 验收物 |
|---|---|---|
| 0 骨架与地图 | `train/` 目录与工具链；地图池生成脚本（复用 mapeditor Generator：mode=plain、row∈[9,15]、column∈[11,17]、先手据点 3 / 后手 4） | 100 张训练图池 + `train/eval-maps/` 预留 |
| 1 评估层 | 共享设施（战场消耗 BFS、割点判定、断连模拟封装、0-1 防护 BFS）→ E_ape（4 特征）→ E_te（6 特征、双快照、T 双权重、种子权重）；手工小局面单测逐特征验证 | 可独立调用的评估模块 + 单测 |
| 2 行动阶段算法 | 按行动文档 v1.5 实现三段式（前置 / 5 基础行为 / 规则 1/2 链推进 / 自杀消耗战 / 兑换 / 原点剪枝 / top-2 / 防守段），输出 **top-4**；逐条行为定义对拍单测 | 行动方案生成器 + 单测 |
| 3 加点算法 | 割点识别（**参数化**：E_ape 坏型带威胁排除、规则 1 防守对象不排除）→ 规则 1 → 规则 2 → 规则 3（E_te 探测 + 局面哈希抽签）；与行动候选组合成完整回合计划 | 完整候选计划生成器（每节点 4 候选）+ 单测 |
| 4 MCTS 引擎 | 回合级树 / UCB1 / 300 模拟 / 叶评估缓存 / min 回传 / argmax 与温度采样两种根决策模式；小局面手工推演单测 | **可对弈的种子权重 AI**（冒烟自对弈可跑、可人工观棋） |
| 5 训练管线 | 对局驱动（isAI=false 双方、意图逐条提交、上限判平）→ 样本收集（双视角双快照 JSONL）→ 拟合器（跨局 pairwise + 平方反比 + L2/SGD）→ 主进程 + worker（先单 worker）→ 验收脚本（argmax vs 基准、eval-maps、胜率曲线） | 端到端训练管线冒烟通过 |
| 6 空转与训练 | 种子权重空转（意图拒绝率、局长分布、样本合理性检查）；**性能 profile → 决定是否切换轻量 E_te（§2.2 性能预案）**；正式训练 + 每 500 局验收 | 训练权重 + 胜率曲线 + 验收报告 |

**原则**：
1. 严格按依赖分层，下层未测稳不上层；
2. 共享设施（战场 BFS / 割点 / 断连模拟）**一次实现、多处复用**（E_te 特征 3/4/5、E_ape 特征 3、加点规则 1/2），避免多份实现漂移；
3. 阶段 4 结束即有"可对弈的种子权重 AI"，可提前人工观棋做 sanity check；
4. 性能预案（轻量 E_te）不预先实现，阶段 6 profile 实测后再决策。
