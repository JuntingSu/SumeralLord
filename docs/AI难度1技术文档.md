# AI 难度1（普通难度）技术实现方案

> **用途**：难度1 AI 策略的实现依据。本文档将《AI行动规则.md》难度1部分与项目架构（`packages/shared/src/game`、`backend/src/ws`、前端对局 store）结合，并固化规则中所有歧义处的最终语义，作为编码蓝本。
> **版本**：2026-09-07（分支 feat/ai-difficulty-1）。
> **前置文档**：《AI行动规则.md》《数字领主战斗规则-v2》《数字领主-M5开发流程设计》。

## 1. 目标与约束

### 1.1 目标

为难度1（普通难度）AI 实现真实的回合决策：行动阶段按规则发起移动/进攻，加点阶段按规则分配点数。**AI 决策以意图形式进入意图流**，与玩家意图同构；对局日志完整记录 AI 行为，回放直接应用记录意图、无需重新运行 AI。难度 2/3/255 保持现有"跳过"语义（以显式 `SWITCH_PHASE` 意图入流）。

### 1.2 硬约束（P7 确定性）

- 决策函数位于 `packages/shared/src/game/ai.ts`，在确定性 lint 作用域内：**零 `Math.random` / `Date.now` / `new Date()`**、全整数运算、排序必须带全序 comparator（`eslint.config.mjs`）。
- **AI 意图与玩家意图同构进入意图流**：占用 eventId、随对局日志持久化（JSONL）、经 `INTENT_BROADCAST` 广播、由各端 reducer 以玩家同一路径应用（校验/演算/事件链/共识完全复用）。
- 回放一致性：回放逐条应用日志中记录的意图即可，**不运行 AI 决策**。
- 决策仍需确定性：提交方切换时从同一状态可重算出一致决策、决策可审计、任一客户端可校验。

### 1.3 随机性处理（种子化 PRNG）

规则多处要求"随机"（扩张随机选空平原、加点随机分配），与零随机约束冲突，处理方式为**种子化确定性 PRNG**：

- 服务器每局生成 seed（`randomBytes(8).toString('hex')`），随 `GAME_START` 下发并持久化为回放日志首行（`backend/src/game/manager.ts` BM7a），回放数据源天然具备。
- seed 经 `InitStateInput` 透传入 `GameState`；决策函数 `planAiTurn(state, seat)` 从 `state.seed` 读取。
- 新增确定性 PRNG：初值 = `FNV-1a(seed)`（复用 `hash.ts`），xorshift32 整数递推，`next()` 返回 32 位无符号整数；"随机选一"= `candidates[next() % candidates.length]`。
- **随机调用点固定**，决策流程中仅在以下三处调用 PRNG（顺序不可变，保证可复现）：
  1. 状态Ⅰ 步骤3：扩张随机选空平原；
  2. 状态Ⅱ 步骤C：随机选"沿海据点 / 沿海平原"类别；
  3. 状态Ⅱ 步骤C / 超支分支：逐点随机选择目标兵。
- 同 seed + 同局面 → 同决策；不同 seed → 决策不同但各自可复现。

## 2. 信息可见性

难度1（普通难度）可获取：

1. （无迷雾）当前棋盘所有地块的地形、兵力、兵所属势力、兵的反击次数、兵的行动力（仅自己回合）；
2. 所有势力基础信息（存活状态和队伍）；
3. 是否是自己回合，是的话在哪个阶段；
5. 游戏规则。

**不可获取**：所有势力的点数信息（信息4）。即难度1**不知道其他势力的点数**（不用于预测/决策）；**己方当前可用点数必然知道**（己方势力状态的一部分，加点阶段必需）。

## 3. 总体架构与接入方式

### 3.1 决策与提交方

- **决策函数**：`planAiTurn(state: GameState, seat: number): AiTurnPlan`（shared 导出、纯函数）。难度1 返回 `{ kind: 'intents', intents: PlayerIntent[] }`；难度 2/3/255 返回 `{ kind: 'skip' }`（保持现有语义，驱动侧展开为连续 `SWITCH_PHASE` 提交直至回合结束，与现状跳过行为等价）。
- **reducer 不再内建调用 `planAiTurn`，不再自动完成 AI 回合**。轮到 AI 席位时，对局正常进入其回合（准备阶段内容照常执行），然后停在 ACTION / ADD_POINT——与玩家回合一致，等待提交的意图推进。
- **提交方**：本局**在线参战玩家中 userId 最小者**。各客户端依据房间数据（`RoomData.players` 的 `online` 与席位）用同一规则推导，无需服务器指定。提交方负责在"当前轮到 AI 席位"时生成并逐条提交该 AI 的意图序列；非提交方（含观战）只应用广播，不提交。
- 提交方掉线 → 其余客户端重新推导，次小 userId 者接管（从最新状态重新规划）；提交被拒（竞态兜底）→ 基于最新状态重新规划。

### 3.2 意图入流（新消息 AI_INTENT_SUBMIT）

新增 WS 消息（客户端 → 服务器）：

```
AI_INTENT_SUBMIT { type: 'AI_INTENT_SUBMIT', clientTempId: string, aiSeat: number, intent: PlayerIntent }
```

服务器处理（会话/中继逻辑，非游戏逻辑；服务器不跑 reducer）：

1. 校验：对局进行中（`game.status === 'in_game'`）；发送者为参战玩家（有席位）；`aiSeat` 为该局 AI 席位（`game.seatAssignments[].isAI`）；
2. 分配 eventId → 持久化 → 广播 `INTENT_BROADCAST { from: 'AI', fromSeat: aiSeat, intent, eventId }` → 回发送者 `INTENT_ACK`。

`INTENT_BROADCAST.from` 语义扩展为 `playerId | 'SERVER' | 'AI'`。

各端对 `fromSeat = aiSeat` 的广播以 actor `{ kind: 'PLAYER', seat: aiSeat }` 调用 `applyIntent`——与玩家意图同一路径，reducer 校验（当前回合席位）、演算、事件链、共识上报完全复用，无需为 AI 增加 Actor 类型。

### 3.3 reducer 改动

- 删除 `runPreparePhaseContent` 中的 AI 分支（`planAiTurn` 内建调用与 skip 循环）及 `planAiTurn` 的 import。
- 保留通用自动跳过逻辑（`autoSkipActionPhase`：进入行动阶段无可动兵自动切加点；加点使点数归零自动切阶段结束回合）——对 AI 与玩家一视同仁，减少冗余意图。
- 行为变化：`initState` 不再自动跳过 AI 回合；AI 回合的全部动作（含跳过）以显式意图进入意图流。

### 3.4 内部模拟（决策依赖最新状态）

规则语义"执行一步操作后重新判定"要求决策必须基于**最新状态**。实现方式：`planAiTurn` 内部以克隆状态为工作状态逐步模拟：

- 每一步决策基于当前模拟状态；
- 选中动作 → 生成对应 `PlayerIntent` 记录到意图序列 → 对模拟状态调用 `applyIntent`（actor = `{ kind: 'PLAYER', seat }`）→ 以返回的新状态继续；
- 模拟应用与真实应用**共用同一个 reducer**，故校验一致：模拟中可执行的意图在真实应用时必然可执行；MOVE 意图目标为敌兵格时 reducer 自动转进攻的行为在模拟中同样发生，结果天然对齐；
- 模拟只覆盖当前 AI 席位的本回合：回合结束（`currentSeat` 变化）即终止，不延伸进入下一席位的决策。

### 3.5 提交节奏与驱动循环

提交方在前端对局 store 内实现 **AI 驱动**：

- 触发：每次本地状态更新后（开局、`INTENT_BROADCAST`/`INTENT_ACK` 应用后、重连追平后），若 `currentSeat` 为 AI 席位、`phase` 为 ACTION / ADD_POINT、且本端为提交方 → 为当前 AI 席位规划并提交；
- 规划：调用 `planAiTurn(本地权威状态, aiSeat)` 得到意图序列（`skip` 则展开为连续 `SWITCH_PHASE`）；
- 提交：**逐条**发送 `AI_INTENT_SUBMIT`，收到 `INTENT_ACK` 后提交下一条；某条被拒（本地 reducer 拒绝）→ 基于最新状态重新规划；
- 该 AI 回合结束后（`currentSeat` 变化），若新的当前席位仍为 AI，重复上述流程（连续 AI 席位依次推进）。

### 3.6 回放

- 回放数据源 = GAME_START + 意图流（含 AI 的 `INTENT_BROADCAST`）。
- Replay 逐条 `applyIntent` 应用记录意图（actor seat = `fromSeat`），**不运行 `planAiTurn`、不介入 AI**。
- seed 仍随 GAME_START 传入 `initState`（构造 `GameState` 一致；回放过程不使用 AI 决策）。

### 3.7 阶段可达性

`runPreparePhaseContent` 在切入行动阶段后结束，此时 `phase` 只可能是 `ACTION`（正常）或 `ADD_POINT`（自动跳过行动阶段后）。PREPARE/END 分支在当前同步模型下不可达：PREPARE 自动流转 ACTION，AI 只在回合开始时被驱动一次；规则中"等待1s后重新查询当前状态"对应外部轮询模型，本架构不适用、不实现。

## 4. 顶层决策逻辑

| 局面 | 操作 |
|---|---|
| 不是自己回合 | 不行动（提交方仅在轮到 AI 席位时驱动） |
| 自己回合 · 行动阶段 · 有可动兵 | 进入状态Ⅰ |
| 自己回合 · 行动阶段 · 无可动兵 | 跳过阶段（reducer 通用自动跳过已处理，AI 无需提交行动意图） |
| 自己回合 · 加点阶段 · 有点数 | 进入状态Ⅱ |
| 自己回合 · 加点阶段 · 无点数 | 跳过阶段（提交 `SWITCH_PHASE` 结束回合） |

## 5. 术语与基础判定（全文共用）

- **敌兵 / 敌对**：中立势力（野生 owner=0 / 阻挡 owner=255）+ 非同队势力。**友兵**：同队兵（含同势力与同队其他势力）。
- **周围**：6 邻格（`neighborsOf`）。
- **进攻力**：连兵 = 兵力 − 1；断兵 = 兵力。
- **可动兵池**：当前势力所有满足 `hasMovement === true` 且非（连兵且兵力 1）的兵（与 reducer 可动判定 `hasMovableSoldier` 一致；兵力1连兵虽有行动力标记也无法执行任何意图）。
- **空平原**：地形 = 平原（PLAIN，编码 0）且无兵的地块。**仅限 PLAIN**，不含海洋、空据点。
- **沿海 / 内陆**：沿海 = 所在地块邻接至少一个海洋（OCEAN）地块（与占据无关）；内陆 = 非沿海。
- **连通图**：由半断 / 可接 / 全接三种连通性地形组成的地形图（**与兵占据无关**）；全断地形不在此图中。
- **反击次数**：`counter`，据点兵为 `COUNTER_INFINITE`，阻挡兵恒为 0。

## 6. 状态Ⅰ：行动阶段

约定：使用兵的坐标作为兵的 index。

### 6.1 步骤1：可动兵池与排序

构建可动兵池（§5），按以下优先级排序生成**正序**列表，倒转得**逆序**列表：

1. **分层**（升序）：① 连兵，或周围有敌兵的断兵（记为层级 0）；② 周围无敌兵的断兵（层级 1）。
2. **兵力**降序。
3. **坐标**升序（含 6.1.1 坐标交换例外）。

#### 6.1.1 坐标交换例外

排序进入坐标比较（即被比较的两个兵同层且同兵力）时，设被比较的两个兵为 A、B，兵力均为 x：

- 前置：该势力可动兵池中兵力恰为 x 的兵**恰好只有 A、B 两个**。
- 统计 **C 类兵** = 该势力中同时满足以下三个条件的兵：
  1. 兵力 > x；
  2. 存在可移动方向——周围 6 格中至少一个地块既不是全断地形也不是友兵占据（**敌兵占据格视为可移动方向**）；
  3. 具有行动力（`hasMovement`）。
- 若 C 类兵**恰好 1 个**，且该 C 的坐标同时大于 A、B 的坐标，则**交换 A、B 的坐标判定结果**（坐标大的兵反而排在前面）。

### 6.2 判定步骤（步骤2~7）

判定按步骤顺序执行；**一旦存在通过当前步骤所有判据的兵，立即执行对应操作**，然后回到 6.1 基于最新状态重新构建池、重排、从步骤2重新判定。仅当所有可动兵均不满足某步骤的判据时才进入下一步骤。

| 步骤 | 顺序 | 判据 | 操作 |
|---|---|---|---|
| 2 正攻判定α | 正序 | 该兵周围存在反击次数 = 0 的敌兵 | 进攻这些无反击敌兵中**兵力最大**者（无进攻力门槛；进攻失败时因敌兵无反击，己方仅失去移动力，属安全消耗） |
| 3 扩张判定 | 正序 | ①该兵是连兵 ②该兵周围存在空平原 | 获取周围所有空平原，**随机**移动到其中一个 |
| 4 正攻判定β | 正序 | ①该兵周围存在反击次数 > 0 的敌兵 ②存在至少一个相邻敌兵兵力 ≤ 该兵进攻力（"进攻力不低于敌兵兵力"） | 进攻这些有反击敌兵中**兵力最小**者（原文"不具有反击力"为笔误，已更正为"具有"） |
| 5 移动判定 | 正序 | ①该兵是断兵 ②可到达直线距离最近的敌对据点（见 6.2.1） | 用 A* 规划到该据点的路径，沿路径**移动一格**（见 6.2.2） |
| 6 夹击判定 | 逆序 | 见 6.2.3 | 进攻夹击目标敌兵 |
| 7 敢死判定 | 逆序 | 见 6.2.4 | 进攻周围兵力最大的敌兵（自杀牺牲） |

#### 6.2.1 步骤5 目标据点与可达性

- **目标据点**：所有敌对据点（敌兵占据的据点性地块，含中立兵占据）中，与该断兵 hexDistance 最小者；多个同距取**坐标小者**优先。同队其他势力的据点不算敌对（不可进攻）。
- **可达性判定**：在连通图（§5，仅地形、忽略占据）中，断兵所在格与目标据点格连通。

#### 6.2.2 步骤5 A* 路径

- 起点 = 断兵所在格，终点 = 目标据点格；启发式用 hexDistance（可采纳）。
- **通行规则**：排除全断地形与有**友兵**占据的格；**不排除敌兵占据的格**（也即允许空格与敌兵格）。
- 取路径第一步发起 MOVE 意图。若第一步目标为敌兵格，MOVE 意图经 reducer 自动转进攻——符合"路径不排除敌兵格"的语义。
- 断兵（兵力 > 1）移动后仍保有移动力（规则 §4.3 仅兵力1断兵移动后失活），同一回合可沿路径连续行军多格；每发起一格移动后回到 6.1 重新计算（重新选目标/路径）。

#### 6.2.3 步骤6 夹击判定

记录该兵周围敌兵坐标 x₁, x₂, …：

1. 周围存在反击次数 > 0 的敌兵，且不存在反击次数 = 0 的敌兵；
2. 该兵进攻力 < 周围敌兵中兵力最小值；
3. 该兵所在格不是据点性地块；
4. 存在**友兵-敌兵对** (y, z)：y 满足
   (a) 与 x 同队不同势力，**或**同势力且还有行动力（同队不同势力的友兵不限行动力；同势力友兵必须有行动力）；
   (b) y 位于某个 z（z ∈ {x₁, x₂, …}）的周围；
   (c) y 的进攻力 + x 的进攻力 > z 的兵力（**针对该对中的敌兵 z 比较**）。

操作：在所有满足判据4的 (y, z) 对中，取 z 兵力最大的一对，令 x 进攻 z。

#### 6.2.4 步骤7 敢死判定

判据 1~3 同 6.2.3。判据 4：存在友兵 y（与 x **同队伍，含同势力**）满足：

(a) y 周围 6 格均为同队兵或不可通行地形（不存在合法移动方向）；
(b) y 进攻力 ≥ 2；
(c) y 不在 x₁, x₂, … 中任何一个的周围。

操作：令 x 进攻 x₁, x₂, … 中兵力最大者。该进攻必败（判据2），且周围敌兵均有反击次数 → 进攻失败后 x 被删除——**自杀牺牲**，以削弱最强敌兵。

### 6.3 循环与终止

- 每执行一个操作后回到 6.1（基于最新状态重判）；
- 一轮步骤2~7 均无任何兵满足任何步骤 → 生成 `SWITCH_PHASE` 意图（进入加点阶段）；
- 模拟应用中若 `phase` 已因 reducer 自动跳过（无可动兵）变为 `ADD_POINT` → 不再重复生成 `SWITCH_PHASE`。

## 7. 状态Ⅱ：加点阶段

### 7.1 分类与指标

**只统计连兵**（断兵无法加点，reducer 会拒绝；海洋为半断地形恒为断兵，天然不在内）。按地形将连兵分为四类，处理顺序固定：

1. 沿海据点；2. 内陆据点；3. 沿海平原；4. 内陆平原。

指标（口径按规则字面，两者不同）：

- **防守压力** d(x) = max{0, 坐标 x 的兵周围**所有敌兵的进攻力之和** − x 的兵力 + 1}
- **进攻阈值** a(x) = max{0, 坐标 x 的兵周围**敌兵中兵力的最大值** − x 的进攻力 + 1}

（敌兵进攻力与 x 进攻力均按 §5：连兵 = 兵力 − 1，断兵 = 兵力。）

类合计：D_k = Σᵢ d(xᵢ)，A_k = Σᵢ a(xᵢ)。

### 7.2 分配流程

设当前可用点数为 P（模拟状态的 `force.points`）：

**步骤A（防守压力）**：按 沿海据点 → 内陆据点 → 沿海平原 → 内陆平原 顺序：

- 若 D_k ≤ P（**等号按可负担处理**）：为该类每个 d(x) > 0 的连兵加 d(x) 点（d(x) = 0 跳过，协议要求 amount 为正），P 减少 D_k，处理下一类；
- 若 D_k > P：**逐点随机**将 P 全部分配给该类连兵，回合结束（不再进入后续步骤）。

**步骤B（进攻阈值）**：步骤A 结束后若 P > 0，重新计算全部 a(x)（兵力已因步骤A变化），按同样顺序：

- 若 A_k ≤ P：为该类每个 a(x) > 0 的连兵加 a(x) 点，P 减少 A_k；
- 若 A_k > P：逐点随机将 P 全部分配给该类连兵，回合结束。

**步骤C（剩余随机）**：步骤B 结束后若 P > 0：

- 随机选择"沿海据点 / 沿海平原"两类之一（无先后顺序）；
- 将 P **逐点随机**分配给该类连兵；
- 若该类无可加点连兵，点数保留不分配（回合自然结束）。

**逐点随机**：循环剩余点数次，每次从该类可加点连兵中随机选一个，其获得点数 +1。

**回合结束**：P 归零时 reducer 在加点后自动切阶段结束回合；若流程结束后 P > 0（仅步骤C 无法分配时可能），生成 `SWITCH_PHASE` 结束回合。

### 7.3 意图生成

- 逐点随机确定每个兵获得的点数后，**按兵聚合**为单个 `ADD_POINT` 意图（`amount` = 该兵获得的总点数），生成顺序按坐标升序（确定性）。
- 模拟应用时若某次 `ADD_POINT` 使 `points` 归零，reducer 自动切阶段结束回合，后续意图不再生成（意图序列在此截断）。
- 分配流程确认无剩余点数需要手动结束时，末尾不加 `SWITCH_PHASE`（reducer 自动处理）；有剩余（步骤C 未分配出去）时追加。

## 10. 边界与防御

- 模拟中 `applyIntent` 失败在理论不可达（池定义与 reducer 校验一致），出现时防御性跳过该意图继续循环，不中断；真实提交被拒（竞态兜底）→ 提交方基于最新状态重新规划。
- 兵力1连兵不入可动兵池；加点目标恒为连兵（与 reducer 校验一致）。
- 无可动兵 / 无点数时 reducer 的通用自动跳过已处理，AI 不提交冗余行动意图。
- 模拟循环设轮数上限（防御极端棋盘死循环）；上限内正常终止，超过则直接结束行动阶段。
- 步骤5 若 A* 无路（终点不可达或全部路径被友兵封锁），该兵不满足判据2，自然落入后续步骤 / 结束行动阶段。
- **提交方一致性**：提交方规则由各端按房间数据确定性推导；在线状态短暂不一致导致的重复提交由 reducer 拒绝兜底（日志可能偶发一条被拒意图，可接受）。
- **全参战玩家离线且轮到 AI 席位**：对局停滞，与"玩家回合全离线"同级（无提交方/无玩家意图驱动），依赖现有断线投降与重连机制；无存活人类势力时的终局规则（防死锁）保持现状，不在本次改动范围。
