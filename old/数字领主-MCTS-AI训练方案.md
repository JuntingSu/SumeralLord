# 数字领主 MCTS AI 训练方案（1v1）

> 状态：设计定稿（2026-09-17），待实施。本文档为可执行计划，决策记录见 §1，里程碑见 §4。
> 适用范围：**1v1 对局**；最终目标：纯 MCTS AI 具备**任意随机地图**作战能力，作为评测基准与游戏内 AI 难度 2/3 的落地方案。

---

## 0. 目标

- 训练一个**纯 MCTS AI（n）**：无神经网络，通过调参（叶评估权重、搜索常数、预算）获得强于规则 AI（难度 1）与参考 MCTS（m）的棋力；
- 建立**优势评估函数 b**（每张地图的先手胜率基线），用于终端奖励中心化与评测归一化，使"后手 45% 值得鼓励、先手 80% 可能不优秀"可量化；
- 建立**随机地图池 + 评测协议**，保证 n 在任意新图上可用，而非背图。

## 2. 总体架构

```
地图生成器（均衡参数）───► 图池（100 张 JSON）───► 每图 b（m vs m, N=200, CI 过滤）
                                                          │
         m（参考 MCTS，固定参数）◄── b 与图池 ──► n 调参管线（随机搜索 → 贝叶斯/CMA-ES）
         │                                               │
         └──── 多对手评估（m / 规则 AI / 不同预算 m）◄────┘
                          │
                     评测报告（按 图×座次 分列 + logit 优势 + 成对赛）
                          │
                     部署：ai-bot 架构，MCTS 决策替换 planAiTurn（难度 2/3）
```

复用件：`@dl/shared` 的 `initState / applyIntent / listAiActions / planAiTurn`（规则 AI 作 rollout 与辅助对手）；`backend/scripts/gen-maps.mjs` 的种子化 LCG 思路；`mapeditor/js/generator.js` 的均衡权重与连通性算法。

## 3. 关键公式与参数

### 3.1 叶评估（截断处）

见《数字领主-MCTS-AI训练-局面评估设计v3.md》

### 3.2 终端值与截断

```
终端：    R = 5·(outcome + (1 − 2p̂))    outcome ∈ {+1, −1}（该节点视角玩家的胜/负）
         p̂ = b（该玩家为先手）/ 1−b（后手）     → 均衡下 E[R] = 0
截断：    R = −0.9 × 5 = −4.5（随终端倍率缩放，保持"截断≈近败"语义；平坦，不做角色调整）
```

终端 ×5（2026-09-17 用户修正）：让终局胜/负（±5）主导叶值（~±1+附加项），搜索优先转化线，解决"堆兵力不攻据点"的磨局问题。

### 3.3 b 的估计与图池过滤

```
每图：m vs m 打 N=200 局（变化 gameSeed + aiRngSeed；固定座次↔出生点，seat1=先手）
     b̂ = seat1 胜率；SE = sqrt(b̂(1−b̂)/200) ≈ 3.5%
剔除：b̂ > 0.8 + 1.64·SE（≈0.858）或 b̂ < 0.2 − 1.64·SE（≈0.142）   ← 置信区间过滤，非点估计
补齐：生成 3×剔除数新图，逐图测，满足 0.2 < b̂ < 0.8 入池；池满 100 停；最多 5 轮，不满则修生成器
极端图集：被剔除图另存，用于鲁棒性诊断
```

成本量级：~150 图 × 200 局 × 0.1~1 局/秒 ≈ 单核 3~15 小时，多核并行（8~16 核）1~2 小时。

### 3.4 MCTS 结构

- **节点** = 状态；**边** = 合法意图（逐意图粒度）：
  - ACTION 阶段：`listAiActions` 枚举（MOVE/ATTACK）；
  - ADD_POINT 阶段：每个可加点连兵 `ADD_POINT(1)` + `SWITCH_PHASE`；
  - `SWITCH_PHASE` 全程可用（引擎自动跳过无可动兵/无点数阶段，不产生空节点）；
- **选择**：UCT（含探索常数 C，调参维度），平局打破 = 种子化随机（受控随机，见 D10）；
- **rollout**：见《数字领主-MCTS-AI训练-局面评估设计v3.md》
- **值传播**：negamax 视角（节点值 = 该节点行动玩家视角）。
- 性能目标：每步 ~300 sims ≤ 1s（单核 TS）。

### 3.5 回合上限（D6）

```
cap(M) = round(c_cap × 地块数)     c_cap 由 M5 标定（池抽样图 m vs m 截断率 < 10%）
```

## 4. 里程碑

### M1 训练模式补丁（reducer）

- `packages/shared/src/game/reducer.ts` 两处（已验证可行，临时补丁测试通过）：
  - `victoryJudgeEvent`（约 :309）：`teams.length > 1 && hasAliveHumanForce` → 训练模式下继续对局；
  - `endTurnEvent`（约 :476）：`!hasAliveHumanForce` 冻结 → 训练模式下正常轮转；
- 实现方式：`InitStateInput.allowAiOnly?: boolean`（默认 false），透传 `GameState.allowAiOnly`，两处条件加判断；
- 验证：纯 AI 1v1 对局跑完（规则 AI 基准：158 局/秒、终局正常、42% 死局与训练协议无关）；现有 tests 回归不破。

### M2 地图生成器（均衡参数 + 公平性约束）

- 移植 `mapeditor/js/generator.js` 的 **plain（均衡）权重 [0.58, 0.02, 0.16, 0.24, 0]** 与全连通逻辑到训练管线（新建 `train/` 目录，仅依赖 `@dl/shared`）；
- `Math.random` → 种子化 LCG（沿用 gen-maps.mjs 思路），生成结果落盘为 MapFullData JSON；
- 参数：尺寸采样（1v1 范围，如 7×10~9×12）、**每方据点数 ∈ {1, 2} 且双方相等**（D13 关键：让 c·S_me 项在训练中生效）、玩家数 = 2；
- 公平性约束：全连通（已有）、双方出生点距离下限、出生点周围可走地形数量近似对称；
- 冒烟：生成 100 张全部能通过 `initState`，每方据点数正确。

### M3 MCTS 核心骨架（m 与 n 共用）

- 实现 MCTS 模块（`train/mcts.ts`）：节点/边/UCT/rollout/叶子/终端/截断（§3.4，§3.1-3.2）；
- 实现对局驱动脚本（applyIntent 循环 + MCTS 决策，参照已验证的规则 AI 基准脚本）；
- **m 固定参数**（默认值）：c=0.1、C=1.0、sims=300、H=16；
- 验收：
  - m vs 规则 AI 胜率（预期 70%+，回合上限下按 §3.5 计）；
  - m vs m 无卡死、记录真实截断率（预期远低于规则 AI 的 42%）；
  - 确定性：同 (gameSeed, aiRngSeed) 同决策。

### M4 图池构建与 b 估计

- 按 §3.3 协议执行（100 图 → 测 b → CI 过滤 → 3× 补齐 → 池满停）；
- 每图产出：`{ mapId, mapJson, b̂, SE, n_games }` 记录文件；
- 并行化：按图并行（worker 进程）；
- 验收：池满 100、极端图集落盘、b 记录完整；抽样复核（每图重测 50 局，|Δb̂| 在噪声内）。

### M5 回合上限标定

- 池内抽样 10~20 图，m vs m 打满 2000 回合，记录结束回合分布；
- `c_cap` = 使截断率 <10% 的最小值（约 = 中位结束回合 × 2，按尺寸桶）；
- 验收：池抽样图截断率 <10%。

### M6 n 调参

- 参数空间（3~4 维）：c（0~0.3）、UCT C（0.5~2.0）、每步 sims（200~2000）、H（8~24）；
- 算法：随机搜索起步（~50 组）→ 贝叶斯优化 / 轻量 CMA-ES；
- 单组评估：多对手混合（D11）× 每对手 60~100 局 × 池中采样图，回合上限按 M5；
- 指标：加权胜率（终端按 b 中心化、截断 −0.9），同时报告截断率与极端图集表现（诊断不参与选参）；
- 过程：评估并行化；**建议中期刷新一次图池**（重新构建，成本 1~2 小时）防池过拟合；
- 验收：n 对 m 汇总胜率稳定 >50%，对规则 AI ≥90%，截断率不劣于 m。

### M7 评测

- 评测集：held-out 池（新生成 20~30 张 + 各自 b）、极端图集、官方 1v1 图（5~7 张，需补测 b）；
- 报告格式：按 (图, 座次) 分列胜率、logit 优势 vs b、截断率；A/B 用成对赛（mirror match，配对消地图优势）；
- 验收：报告模板产出，能回答"后手 45% 是否值得鼓励"（与 b 对比）。

### M8 部署

- 复用 `backend/src/ai-bot` 架构：MCTS 决策接入意图提交流，替换/新增 `planAiTurn` 分支（难度 2/3）；
- 生产随机数 = 局内种子派生（D10），遵守确定性 lint（零 Math.random）；
- 每步时间预算（目标 <2s，适配步时）；
- 验收：与服务器联调，回放一致性，AI 全对局无卡死。

## 5. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| TS 单核 MCTS 性能不足 | 并行化评估；必要时降 sims/H；仅 m 做对手时预算可上调 |
| m vs m 真实截断率未知 | M3/M5 实测；c_cap 依实测标定而非假设 |
| 单据点图 c·S_me 项失效 | M2 据点数参数（每方 1~2 且相等） |
| 调参过拟合 m / 图池 | 多对手混合（D11）+ 池中期刷新 |
| 调参评估噪声 | 每参数集局数预算 + 双种子固定对 |
| b 边界噪声 | CI 过滤（已定） |
| 部署确定性 | 生产随机数局内种子派生，回放不依赖 AI 重跑 |

开放问题（不阻塞实施，实施中定）：
1. 池刷新频率（建议每 ~1 轮调参刷新一次）；
2. 官方 1v1 图的 b 估计时机（进入评测集时补测，N=200）；
3. 难度档位 ↔ MCTS 预算映射（难度 2 = 小预算、难度 3 = 大预算）；
4. 极端图集是否进入最终评分（建议仅诊断列）。
