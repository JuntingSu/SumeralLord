# 数字领主 · 人工示范注入训练 — 修改技术文档

> 版本：v0.1（草案，2026-09-20）
> 状态：待评审
> 关联：《数字领主-MCTS自训练环境设计方案.md》《数字领主-行动阶段决策规则.md》

---

## 1. 目标与背景

现有训练循环（自对弈 → 双快照样本 → pairwise 排序拟合 E_te 权重）中，AI 的行为方向完全由终局胜负信号驱动。为引入设计师的经验，新增**人工示范（Human Demonstration）**通道：

- 用户在 replay-viewer 中浏览自对弈数据，在**任意行动/加点阶段局面**演示自己的操作（MOVE/ATTACK/ADD_POINT/SWITCH_PHASE 序列）；
- 演示自动生成为示范文件存入 `train/demos/`；
- 训练时示范以 **200 倍样本权重**并入拟合窗口，让 E_te 学会高估"用户偏好的局面"——通过价值函数间接模仿用户操作，并能泛化到相似局面。

本阶段**不实现**"精确局面候选注入"（AI 在该局面直接执行用户方案），示范 JSON 预留 `positionHash` 字段以便未来扩展。

## 2. 数据流总览

```
replay-viewer（回放界面）
  │  用户停在某行动阶段局面，点击"示范操作"
  ▼
对局模拟界面（demo 模式）
  │  用户点击棋盘演示 MOVE/ATTACK，可撤销，点击"示范结束"
  ▼
POST /api/demo（vite dev-server 中间件）
  ▼
train/demos/demo-<ts>.json        ← 示范文件
  │
  ▼（训练时，train.ts → demos.ts）
按 sourceGameId 定位源日志 → 重放至 turnStartEventId / startEventId
  → 应用用户 intents → teFeatures(操作后局面, 回合初局面, seat)
  ▼
TrainSample{ features, turn, area, dToEnd:1, label:+1, weight:200 }
  ▼（fitWeights）
与窗口样本合并，pairwise 权重 = Σ sample.weight / d²
  ▼
E_te 新权重（增量拟合，锚点 = 当前权重）
```

## 3. 示范文件规范（train/demos/demo-<ts>.json）

```json
{
  "id": "demo-<ts>",
  "createdAt": "2026-09-20T18:00:00.000Z",
  "sourceGameId": "t-xxxxxx",
  "seat": 1,
  "turnStartEventId": 42,
  "startEventId": 57,
  "positionHash": "8位hex",
  "intents": [
    { "intentType": "MOVE", "from": 3, "to": 9 },
    { "intentType": "ATTACK", "from": 9, "to": 10 }
  ],
  "note": ""
}
```

| 字段 | 语义 | 来源 |
|---|---|---|
| `id` | 唯一标识（时间戳） | viewer 生成 |
| `sourceGameId` | 源对局 id（GAME_START.gameId） | viewer 从日志首行读取 |
| `seat` | 示范所属势力 | viewer：`board.currentSeat` |
| `turnStartEventId` | 该势力本回合开始（ACTION 相位边界）的事件 id——E_te 双快照的"回合初" | viewer 重放时维护（见 §4.3.1） |
| `startEventId` | 用户点击"示范操作"时的事件 id（当前局面 = 重放到此） | viewer：`cursor` |
| `positionHash` | 演示起点局面哈希（`hashGameState`） | viewer 生成（预留） |
| `intents` | 用户操作序列（MOVE/ATTACK/ADD_POINT/SWITCH_PHASE；SURRENDER 除外） | viewer 模拟界面 |
| `note` | 用户备注（可选） | viewer 输入框 |

**约定**：
- 训练侧不依赖浏览器记录磁盘路径，按 `sourceGameId` 扫描 `train/runs/logs/*.jsonl`（GAME_START 首行匹配）定位源日志；
- 一个源对局可导出多个示范（不同 `startEventId`）；
- 删除 `train/demos/` 下文件即移除该示范对训练的影响（无需其他清理）。

## 4. replay-viewer 修改设计

### 4.1 本地写盘通道（vite.config.ts）

浏览器无法直接写本地文件，新增 vite 自定义插件中间件（**仅 dev 模式**；README 注明需 `npm run dev` 使用）。

```ts
// vite.config.ts 追加
{
  name: 'demo-saver',
  configureServer(server) {
    server.middlewares.use('/api/demo', (req, res, next) => {
      if (req.method !== 'POST') return next();
      let body = '';
      req.on('data', (c) => (body += c));
      req.on('end', () => {
        try {
          const demo = JSON.parse(body);
          const dir = path.join(TRAIN_ROOT, 'demos');
          fs.mkdirSync(dir, { recursive: true });
          const file = path.join(dir, `demo-${Date.now()}.json`);
          fs.writeFileSync(file, JSON.stringify(demo, null, 2));
          res.setHeader('Content-Type', 'application/json');
          res.end(JSON.stringify({ ok: true, file }));
        } catch (e) {
          res.statusCode = 500;
          res.end(JSON.stringify({ ok: false, error: String(e) }));
        }
      });
    });
  },
}
```

- `TRAIN_ROOT` = `replay-viewer/..`（即 `train/`）；
- 写文件用 `node:fs` 直接写，不受 vite `server.fs.allow` 影响（后者仅限读）。

### 4.2 回放界面改动（App.tsx，现有 ~331 行）

现有结构（已核实）：
- `parseLog`（:22-44）：只收 `GAME_START` + `INTENT_BROADCAST`；
- `replayTo(n)`（:76-100）：从 `initState` 全量重放到第 n 条意图（`applyIntent` 逐条）；
- 播放循环（:179-204）：`setInterval` 推进 + `EventAnimator` 动画；
- 状态：`mode: 'upload'|'error'|'playing'`、`board: GameState|null`、`cursor/total`、ref 镜像；
- BoardCanvas 接入（:290）：`mySeat={null} ... onTileClick={() => undefined}` —— 全部空实现（纯观战）。

**改动**：
1. 新增 `mode: 'demo'`；
2. 工具栏加"示范操作"按钮：
   - 启用条件：`board !== null && !board.finished && (board.phase === 'ACTION' || board.phase === 'ADD_POINT')`；其余相位禁用并提示"请停在行动或加点阶段"；
   - 点击时采集：`seat = board.currentSeat`、`startEventId = cursor`、`turnStartEventId`（§4.3.1）、`positionHash = hashGameState(board)`；记录当前 board 引用为演示基线（reducer 不可变，`applyIntent` 不改入参，可直接复用引用）；`mode='demo'`。

### 4.3 对局模拟界面（demo 模式）

#### 4.3.1 回合边界记录（turnStartEventId）

在 `replayTo(n)` 与播放推进的逐条 `applyIntent` 循环中，维护 `turnBoundaries: Map<seat, number[]>`（每势力各回合 ACTION 相位开始的事件 id）：

> 应用第 i 条意图后，若结果状态 `phase === 'ACTION' && currentSeat === seat`，且**上一状态的 `currentSeat !== seat`**（或上一状态未到该回合），则 `turnBoundaries[seat].push(i)`（i = 已应用意图数，即事件 id）。

`replayTo` 每次从 0 重放时同步重建该表（成本与重放本身一致，可接受）。取 `turnStartEventId` = `turnBoundaries[seat]` 中 ≤ cursor 的最后一个。

#### 4.3.2 棋盘交互

**BoardCanvas.tsx 不改**（交互协议已完备：props `mySeat/selected/onTileClick/onTileHover/onTilePointerDown/Up`，行动阶段选兵高亮/反击着色 :449-576，Pointer 事件 :589-638）。App 层接线：

- 传入 `mySeat={seat}`、`phase='ACTION'`、`selected={demoSelected}`、`onTileClick={handleDemoClick}`；
- `handleDemoClick(tile)` 模仿 `frontend/src/pages/Game.tsx` 的 `handleTileClick`（:297-331）两步交互：
  1. 点己方有移动力兵 → 选中/再点取消；
  2. 点目标格：敌方兵 → `ATTACK`；空地块 → `MOVE`；同队 → 忽略；
  3. 生成意图后 `applyIntent(demoState, { actor: { kind: 'PLAYER', seat }, intent })` 本地验证：
     - ok → `demoHistory.push(demoState)`（栈存**应用前**状态）、`demoState = r.state`、`demoIntents.push(intent)`；随后按 `Game.tsx` 的 `nextSelectedTile`（:722-731）模式自动续选（目标格新兵仍有移动力则继续选中，便于连击）；
     - 拒绝 → 网页通知原因，不加入、不改状态。
- **切换阶段按钮**：`SWITCH_PHASE` 意图（ACTION → ADD_POINT；ADD_POINT 且有余点 → 提前结束回合），与棋盘操作同一验证/入栈流程；回合随 reducer 推进（如点数用尽 autoSkip / 跨势力）后按钮与棋盘操作自动禁用。
- **加点阶段交互**：`handleDemoClick` 在 `phase==='ADD_POINT'` 时点己方**连兵** → `{ intentType: 'ADD_POINT', coordinate, amount: 1 }`（可连点累计；点数用尽自动结束回合）。BoardCanvas 的 ADD_POINT 高亮（:472-483）在 `mySeat`+`phase` 下自动生效，无需改动。

#### 4.3.3 撤销

- `demoHistory: GameState[]` 状态栈，`demoIntents: PlayerIntent[]` 并行数组；
- "撤销"按钮：`demoState = demoHistory.pop()`，同步 `demoIntents.pop()`；栈空则禁用；
- 撤销范围仅限本次演示（天然不能撤销回回放中）。

#### 4.3.4 示范结束与通知

- 校验：`demoIntents.length > 0`；
- 组装示范 JSON（§3）→ `POST /api/demo`；
- 成功：toast「示范已保存到 train/demos/demo-xxx.json」，自动返回回放界面（`mode='playing'`，board 恢复为回放态）；
- 失败：红字错误提示，停留在模拟界面；
- 顶部"返回"按钮放弃本次演示（直接回回放，不保存）。
- 通知：App 内简易 toast state（`useState<string|null>` + 定时清除），不引第三方库。

## 5. 训练侧集成

### 5.1 train/lib/demos.ts（新文件）

```ts
export interface DemoFile { id; createdAt; sourceGameId; seat; turnStartEventId; startEventId; positionHash?; intents: PlayerIntent[]; note? }

export function loadDemos(dir: string): DemoFile[];              // 读 train/demos/*.json，字段校验
export function demoToSample(demo: DemoFile): TrainSample | null; // 见下
```

`demoToSample` 步骤：
1. 按 `sourceGameId` 定位源日志：扫描 `train/runs/logs/*.jsonl` 的 GAME_START 首行（进程内缓存 `gameId → file` 索引，避免每次拟合重扫；日志增删时按 mtime 重建）；
2. 解析日志（同 viewer 规则）→ `initState`：
   - 重放到 `turnStartEventId` → 校验 `phase==='ACTION' && currentSeat===seat`，得**回合初局面**；
   - 重放到 `startEventId` → 校验 `currentSeat===seat` 且 `phase∈{ACTION, ADD_POINT}`（演示可自加点阶段起步），得**演示起点局面**；
   - 逐条应用 `demo.intents`（actor = seat）——**任何一条被拒绝则整个 demo 跳过并打印警告**（viewer 已保证合法，此处为兜底一致性校验）；
3. 计算 `features = teFeatures(操作后局面, 回合初局面, seat)`；
4. 返回 `TrainSample{ gameId: demo.id, mapId: <源图id>, seat, turn: 操作后局面.turn, area, features, dToEnd: 1, label: 1, weight: 200 }`。

容错：日志缺失 / 图 id 不可得 / 重放不一致 → 返回 null，调用方跳过并警告，不影响训练。

### 5.2 TrainSample 权重（driver.ts + fitter.ts）

- `TrainSample`（`train/lib/driver.ts`）新增 `weight?: number`（缺省 1）；
- `fitWeights`（`train/lib/fitter.ts`）的 pairwise 权重：
  ```
  pairWeight = (wS.weight ?? 1) / d² + (lS.weight ?? 1) / d²
  ```
- 示范样本（`label: +1` 归入胜侧、`weight: 200`、`dToEnd: 1`）以 200 倍权重参与排序学习——即"**200 倍学习权重**"的落点（重要性采样语义）。

### 5.3 train.ts 拟合集成（runFit）

- 每次拟合：`窗口样本 ∪ loadDemos + demoToSample 结果`；
- 拟合日志追加 `示范样本 +N（跳过 M）`；
- 与增量拟合（`--fit-anchor current`）正交：示范样本在每次拟合中持续生效（直到删除 demo 文件）。

## 7. 边界与不做事项（本阶段）

- **不做**精确局面候选注入（AI 直接执行用户方案）；JSON 已含 `positionHash`，未来扩展无需改格式；
- 演示支持行动阶段（MOVE/ATTACK/SWITCH_PHASE）与加点阶段（ADD_POINT）；**不支持 SURRENDER**；回合随 reducer 推进（点数用尽 autoSkip / 跨势力）后棋盘操作自动禁用；
- 不做 demo 编辑/删除/列表 UI（文件系统管理即可）；
- 写盘仅 vite dev 模式（`npm run dev`）；构建产物（`vite preview`）无该端点，README 注明。
