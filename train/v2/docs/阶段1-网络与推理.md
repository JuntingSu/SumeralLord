## 2. 网络（model.py）

- **结构**：`embed(14→d)` → 6 层编码器（相对位置偏置注意力 + FFN）→ LayerNorm；
  - **策略头**：每格 token → 38 logits（6 方向 + 32 加点），CLS → 1 logit（切换阶段）；展平顺序与 TS `actions.ts` 一致（每格交错 + 末尾切换）；
  - **价值头**：CLS → MLP → tanh，当前行动方视角胜率；
- **默认规模**：d=128、6 层、8 头、FFN 512（≈1.2M 参数，CPU 可训）；
- **位置编码**：仅相对位置偏置——tile-tile 按（源行奇偶, Δrow, Δcol）查表（±8 裁剪，奇偶维因 hex 邻接模式随行奇偶变化），CLS 与 tile 间用每头标量桶；无绝对位置嵌入，任意地图尺寸通用；
- **输入**（float32）：`features (B,S,14)`、`rows (B,S)`、`cols (B,S)`（CLS=0；token i>0 = tile i-1 → row=⌊(i-1)/columns⌋, col=(i-1)%columns）、`mask (B,S)`（1=真实）；
- **输出**：`policy (B, nTiles×38+1)`（未掩码 logits）、`value (B,)`。

## 3. 训练（train.py）

- 损失：`loss = 策略 CE + 价值 MSE`；
  - 策略 CE：每样本在**合法动作子集**上 gather logits → softmax → 与 π 的交叉熵（π 覆盖全部合法动作，含 0 概率）；
  - 示范损失（λ_bc × 示范策略 CE）阶段 5 接入；
- 默认：batch 64、lr 1e-3、Adam、10% 验证集、按验证损失保存最佳 checkpoint；
- checkpoint：torch.save（config + state_dict + epoch + val_loss）。

## 4. 导出与一致性（export.py / check_ts.py）

- `export.py`：torch.onnx.export（动态 batch/seq）+ 内置自检（PyTorch vs ONNX Runtime，误差 < 1e-4 才写回）；
- TS↔Python 一致性流程：
  1. `npx tsx v2/scripts/check-onnx.ts`：跑一个真实局面 → TS（onnxruntime-node）推理 → 落盘 `v2/runs/weights/check-ts-dump.json`；
  2. `python v2/python/check_ts.py`：同一局面跑 torch → 对比，误差 < 1e-4；
- 实测误差：policy 3.4e-07 / value 1.3e-08。

## 5. 验证结论（阶段 1 验收）

- 随机策略样本训练：损失收敛到理论下限（π 均匀 → 最优 CE = log 合法动作数 ≈ 3.22）✓；
- 集中式 π 合成样本：CE 3.22 → 1.43，梯度路径正确 ✓；
- ONNX 导出 + TS/Python 前向一致 ✓。

## 6. 已知工程注意项

- 训练吞吐：batch 64、S=145 时前向 ~1.4s/批（CPU）。阶段 3 规模化前考虑：更小 d/layers 或注意力优化；样本二进制化（阶段 0 已记）；
- onnxruntime-node 输入必须显式 `new ort.Tensor(type, data, dims)`（裸 typed array 会报 `Tensor.dims must be an array`）。
