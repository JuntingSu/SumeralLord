# 数字领主 AI 训练 v2 · 阶段 5：人类指导工具

> **用途**：阶段 5 产物说明——四类标注（示范/纠错/偏好局面题/偏好走法题）的数据格式、抽样器、判题工作台与训练集成。
> **版本**：v0.1（2026-09-22）。
> **关联**：《数字领主-AI训练方案v2-整体框架.md》§7（修订版）。

---

## 1. 四类标注总览

| 通道 | 数据来源 | 交互方式 | 训练信号 |
|---|---|---|---|
| 示范 | 人工在回放中自由演示 | 回放器演示模式 | λ_bc × 策略 CE |
| 纠错 | 人工标记"AI 错误 + 正确操作" | 回放器纠错模式 | λ_bc × 策略 CE（同示范） |
| 偏好·局面题 | 抽样器：同图多局回合末局面两两配对 | 判题工作台 | λ_pref × 价值排序 |
| 偏好·走法题 | 抽样器：同一局面的两个候选动作（MCTS 根分布） | 判题工作台 | λ_pref × 价值排序（后继局面） |

## 2. 数据格式（只存引用，规则/编码留在 TS）

- **示范/纠错**（`v2/demos/demo-*.json`，kind 区分）：`{ id, kind, sourceGameId, seat, turnStartEventId, startEventId, intents[], aiAction?(仅 correction), note }`
- **偏好·局面题**（`v2/prefs/pref-*.json`，kind=position）：`{ id, kind, a:{sourceGameId,eventId,seat}, b:{...}, label: a|b|both_bad|unknown, note }`
- **偏好·走法题**（kind=action）：`{ id, kind, sourceGameId, eventId, seat, actionA, actionB, label, note }`
- `label=unknown`（不能判断）在转换时作废不入训练；`pairs-*.json` 是抽样器产出的**题目队列**（未判定），转换器跳过。

## 3. 抽样器（`scripts/sample-questions.ts`，每轮拟合前运行一次）

- **局面题**：按 mapId 分组 → 同图两局、同视角座次的回合末局面配对；近回合优先（|回合差|≤2，不足放宽）；局面哈希种子确定性 + 去重（每局面最多抽 N=3 次）；
- **走法题**：决策点（回合末 = 下一行动方 ACTION）跑当前模型 MCTS（argmax），A = 访问数第一、B = 访问数第二（有区分度；相同则跳过）；
- 产物：`v2/prefs/pairs-<ts>.json`。

## 4. 判题工作台（`v2/replay-viewer`，vite dev）

- 回放器新增三模式：**示范**（沿用 v1）、**纠错**（标记 AI 错误 + 演示正确操作，保存附 aiAction）、**判题工作台**；
- 工作台：上传 pairs JSON → 逐题展示（局面题 = A/B 双棋盘并排；走法题 = 动作文字摘要 + 双后继棋盘并排）→ 四选项（a 好/b 好/都不好/不能判断）+ 跳过 → POST `/api/pref` 落盘；
- vite dev 中间件三个端点：`POST /api/demo` → v2/demos/、`POST /api/pref` → v2/prefs/、`GET /api/log/:gameId` → 按 gameId 返回日志（跨 round 目录扫描）；
- 视角座次：局面题 = 配对座次；走法题 = 位置行动方；价值换算（行动方≠视角取负）在训练侧统一处理。

## 5. 训练集成

- **转换器**（`scripts/annotations-to-samples.ts`，拟合前运行）：日志索引 → 重放 → 编码；
  - 示范/纠错 → `runs/demo-samples/`（每步一条，π = 人类动作 one-hot；ADD_POINT>32 拆分；intent→action 逆映射，MOVE/ATTACK 同索引）；
  - 偏好 → `runs/pref-samples/`（局面题两侧编码 + 视角座次；走法题 apply A/B 得后继局面编码）；
- **损失**（train.py，参数可配）：
  - `loss = 自对弈(策略CE + 价值MSE) + λ_bc × 示范策略CE + λ_pref × 偏好损失`
  - λ_bc 初始 1.0、每轮 ×0.9 衰减（主循环 `--lambda-bc-init/--lambda-bc-decay` 传入）；
  - 偏好损失统一作用于价值：a好 → hinge(v_A视角 − v_B视角 − margin)；b好 反向；都不好 → 双双压向 bad_target（默认 −0.5）；价值按视角座次换算（行动方==视角 ? v : −v，1v1 零和）；
  - 示范/偏好只在训练 batch 生效，验证损失不含。

## 6. 验证结论（阶段 5 验收）

- v2 单测 43 个全绿（新增：intent→action 逆映射、demo/偏好转换、抽样器配对/去重/确定性）；
- 端到端：真实日志 → 生成示范/纠错/偏好（局面+走法）→ 转换 → 样本正确落盘 → train.py 带 λ_bc/λ_pref 跑通；
- 抽样器：6 局日志 → 3 局面题 + 2 走法题；
- viewer：dev 服务启动、三个 API 端点验证通过、生产构建通过；
- v1 全量回归保持全绿。

## 7. 已知工程注意项

- `pairs-*.json` 题目队列与已判定 `pref-*.json` 同目录；转换器只消费 `pref-*`；
- 日志必须保留（标注引用 gameId + eventId）：主循环目前不裁剪 logs（仅裁剪 samples），人工工具依赖日志存在；
- 偏好数据量小（JSONL），体积不是问题；走法题抽样每次拟合前跑一次（~100 题 × MCTS ≈ 分钟级）。
