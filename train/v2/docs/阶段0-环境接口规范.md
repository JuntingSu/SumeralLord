## 2. 状态编码（encode.ts）

- 输入 = 变长 token 序列：**CLS token（1 个）＋ 每格 token（nTiles 个）**，nTiles = 地图格子数（地图尺寸无关）。
- 视角 = 当前行动方相对视角（我方/敌方）。

### 2.1 每格 token（14 维）

| 维度 | 内容 | 取值 |
|---|---|---|
| 0~4 | 地形 one-hot | 平原/据点/海洋/山地/虚空 |
| 5 | 兵力 | 原值；空 = 0 |
| 6~10 | 归属 one-hot | 空/我方/敌方/野生/阻挡 |
| 11 | 连断 | 1 = 连兵；空 = 0 |
| 12 | 移动力 | 1 = 有；空 = 0 |
| 13 | 剩余反击次数 | min(counter, 2)；2 = 据点 ∞ |

### 2.2 CLS token（14 维）

| 维度 | 内容 |
|---|---|
| 0 | 回合数 |
| 1~4 | 阶段 one-hot（PREPARE/ACTION/ADD_POINT/END） |
| 5 | 行动方座次（绝对座次，1v1 为 1/2） |
| 6/7 | 我方/敌方总兵力 |
| 8/9 | 我方/敌方连兵数 |
| 10/11 | 我方/敌方据点数 |
| 12/13 | 我方/敌方当前可支配点数 |

注意：点数在准备阶段**累加**发放（`force.points += 连兵数`，reducer 不重置），加点阶段可提前切阶段、未花完的点数留存到下一回合；仅势力被清除时清零。因此"敌方点数"任意时刻 = 历史累计发放 − 已消耗的余量，**仅开局第一回合（敌方尚未轮到准备阶段）为 0**。

## 3. 动作空间（actions.ts）

动作索引布局（nTiles = 格子数，每格交错排列）：

```
[0, nTiles×6]          每格 6 方向（移动/进攻共用：目标为敌兵时 reducer 自动转进攻）
[nTiles×6, nTiles×38]  每格 32 个加点档（+1..+32）
[nTiles×38]            全局切换阶段
```

- 方向 d 对应 `neighborsOf(tile)` 邻居表第 d 个邻居（越界方向 = 非法，掩码过滤）；
- 合法掩码 `legalMask(state)` 与 reducer 意图校验一一对应，由对拍测试保证：**掩码合法动作必然被 applyIntent 接受**；
- 切换阶段在 ACTION/ADD_POINT 阶段恒合法。

## 4. 样本格式（JSONL，逐局一文件）

每步决策一条记录（**动作前局面**编码 + 动作先验 + 终局标签）：

```json
{
  "gameId": "t-xxxxxx",
  "mapId": "map-001",
  "turn": 1,
  "seat": 1,
  "phase": "ACTION",
  "nTiles": 144,
  "rows": 12,
  "columns": 12,
  "cls": [14 个数字],
  "tiles": [[14 个数字] × nTiles],
  "pi": [[动作索引, 概率], ...],
  "z": 1
}
```

- `rows`/`columns`：地图行/列数，Python 侧据此推导每个 token 的位置（tile i → row = ⌊i/columns⌋，col = i mod columns；token 0 = CLS）与相对位置偏置；

- `pi`：**覆盖全部合法动作**（概率可含 0），索引 = §3 动作空间索引；合计 = 1；
- `z`：行动方视角终局标签，胜 +1 / 负 −1 / 平 0（60 回合或 1000 步判平），终局后回填；
- 对局日志（GAME_START / INTENT_BROADCAST×N / GAME_OVER）与线上同构，可直接回放。

## 5. 已知工程注意项（后续阶段处理）

- **样本体积**：每条 ~8KB（tiles 数组为体积大头），1000 局 ≈ 8GB。阶段 3 训练循环落地时需换二进制/base64 或压缩格式（本格式保留，转换器在采样侧做）；
- 随机策略冒烟：整局意图拒绝数 = 0（掩码正确性的端到端证据）；
- 驱动在非 ACTION/ADD_POINT 相位抛错（防御；reducer 静止态只可能在这两个相位）。
