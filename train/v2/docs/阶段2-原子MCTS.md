## 1. 代码与接口

- `v2/lib/mcts.ts`：`mctsDecide(state, net, opts)` → 根动作 + 访问分布；`mctsPolicy(net, opts)` → 接入 driver 的异步策略；
- `v2/lib/driver.ts`：`Policy` 支持同步/异步（`playGame` 已异步化）。

```ts
interface MctsOptions {
  simulations: number;      // 模拟次数（训练数据生成 5~200 随机；验收/评估 1000；部署 200）
  explorationC?: number;    // PUCT c（缺省 1.0）
  temperature?: number;     // 根温度采样（缺省 0 = argmax；训练传 >0）
  rng?: () => number;       // 训练采样随机源
}
```

## 2. 搜索语义（与决策定稿 §5 逐条对应）

| 决策 | 实现 |
|---|---|
| 树结构 | 原子节点；节点 = 一个动作后的局面；子节点在**展开时**经 `applyIntent` 创建（父局面不可变） |
| 符号语义 | 节点价值存**该节点行动方视角**（网络输出恒为当前行动方视角，天然对齐）；回传时沿路径向上，**行动方变化的边取负**（同一玩家连续动作不翻转）；选择时父节点把子节点价值换算回父视角（行动方不同取负）再取 max——对手节点等效取 min |
| PUCT | `score = Q + c·P·√N / (1+n)`；Q = 父视角平均价值；P = 网络先验（展开时对合法动作 softmax）；并列取动作索引小者（确定性） |
| 根全动作展开 | 每次决策先展开全部合法动作并各评估一次（决策定稿 §5：一步深 + 价值网络即可识别先亏后赚） |
| 叶评估 | 终局 = 精确值（胜 +1/负 −1/平 0）；非终局 = 网络价值（展开时缓存） |
| 根决策 | τ=0 → 访问数 argmax；τ>0 → prob ∝ visits^(1/τ) 采样 |
| π（训练目标） | 根访问比例（覆盖全部合法动作，prob 可含 0；根未访问时均匀兜底） |
| 确定性 | 搜索无随机；同局面同权重同模拟数 → 同动作（单测覆盖） |

## 3. 性能基线（CPU，onnxruntime-node）

- 单次前向 ~8ms（S≈130）；每模拟 = 1 次前向 + 若干 applyIntent；
- 数据生成（随机 5~200 模拟）：约 0.04~1.6s/步；部署 200 模拟 ≈ 1.6s/步（+ 5s 兜底满足）；
- 1000 模拟 ≈ 8s/步——留给验收/评估用，不进自对弈数据生成。

## 4. 验证结论（阶段 2 验收）

- 29 个 v2 单测全绿（新增 6 个 MCTS 测试：确定性、动作合法、根全展开、温度采样、端到端零拒绝、终局防御）；
- 端到端：MCTS 策略（40 模拟/步）在 5×5 测试图完整对局、0 拒绝；
- 全量回归：v1 96 测试、v2 29 测试、三个 tsconfig typecheck 全绿。

## 5. 已知工程注意项

- 每决策的树节点 ≈ 模拟数（每节点持有 GameState），1000 模拟 ≈ 数 MB 内存，可接受；
- 训练数据生成的随机模拟数（5~200）由阶段 3 的调度器注入 `simulations`；
- 若未来需提升吞吐：批量叶评估（一次前向多叶）、更小网络（d=64/4 层 ≈ 2~4 倍提速）、样本二进制化（已记）。
