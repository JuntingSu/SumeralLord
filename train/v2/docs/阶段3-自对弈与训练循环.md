# 数字领主 AI 训练 v2 · 阶段 3：自对弈与训练循环

> **用途**：阶段 3 产物说明——训练主循环的组件与流程。阶段 4（验收）按本规范接入基准 AI 与验收脚本。
> **版本**：v0.1（2026-09-22）。
> **关联**：《数字领主-AI训练方案v2-整体框架.md》§6/§8、《阶段0~2》文档。

---

## 1. 组件

```
v2/
├── lib/pool.ts            # 对手池：20 checkpoint、随机抽取、接受/裁剪（pool.json 持久化）
├── lib/sampleio.ts        # 二进制样本写入（.bin，训练循环用；JSONL 保留给调试/小规模）
├── python/init_model.py   # 种子模型 v0（随机初始化 + ONNX 导出自检）
├── python/data.py         # 样本加载：优先 .bin，否则 .jsonl
├── python/train.py        # 拟合（--max-samples 子采样控制 CPU 成本）
├── scripts/worker.ts      # worker 子进程：selfplay（出样本）/ gate（门限对局）两类任务
└── scripts/train-v2.ts    # 主循环入口
```

## 2. 主循环流程（每轮）

```
1. 自对弈 gamesPerRound 局（worker 并行）
   每局：地图轮转（100 张训练图池）；双方从对手池独立随机抽模型；
   每步：模拟数随机 [5,200]（playout cap randomization）+ 温度采样 τ(gamesDone)；
   产物：二进制样本（round-XXXXX/）+ 对局日志（供回放/人类工具）
2. 拟合：python train.py（本轮样本，--max-samples 子采样，epochs/lr 可配）
         → python export.py（ONNX + 自检）
3. 门限对局：新权重 vs 当前权重，argmax 固定模拟数（默认 100），验收图池，先后手交替
   胜率 ≥ 55% → 接受（进对手池、成为 current）；否则丢弃
4. 曲线/状态：curve.csv 追加、state.json/pool.json 更新、旧轮样本裁剪（保留 2 轮）
```

## 3. 配置参数（train-v2.ts）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--workers` | CPU 核数（16） | worker 子进程数 |
| `--games-per-round` | 1000 | 每轮自对弈局数（拟合节奏） |
| `--gate-games` / `--gate-sims` | 100 / 100 | 门限对局数 / 固定模拟数（argmax） |
| `--data-sims-min/max` | 5 / 200 | 每步随机模拟数范围 |
| `--tau-start/end/games` | 10 / 0.5 / 10000 | 温度线性退火（之后恒 0.5） |
| `--epochs` / `--lr` | 3 / 1e-3 | 拟合超参 |
| `--max-samples` | 300000 | 拟合子采样上限（CPU 成本控制） |
| `--max-rounds` / `--max-steps` | ∞ / 驱动默认 | 轮数上限 / 单局步数上限（判平） |

## 4. 二进制样本格式（TS 写 / Python 读）

记录布局（小端，逐条拼接）：`u32 S, u32 rows, u32 cols, u32 L, f32 z, f32[S×14] features, u32[L] legal, f32[L] target`。
位置由 Python 按 rows/cols 推导。往返一致性由 `temp/check-binary.ts` + `python/check_binary.py` 验证（与 JSONL 解析完全一致）。

## 5. 验证结论（阶段 3 验收）

- 端到端冒烟（2 workers、3 局/轮、2 轮）：种子模型 → 自对弈 → 拟合（loss 2.31→2.03）→ 导出 → 门限（v1/v2 均 50% < 55% **正确拒绝**）→ 曲线/状态落盘；
- 门限机制正确性：未充分训练的模型被拒绝，对手池保持 [v0]；
- 二进制格式往返一致；pool 单测 4 项；v1+v2 全量测试与 typecheck 全绿。

## 6. 已知工程注意项

- **吞吐**（CPU，16 核，前向 ~8ms）：数据生成 avg ~100 模拟 ≈ 0.8s/步，单局 ~5~13 min（视步数）；1000 局/轮 ≈ 12~16 h；门限 100 局 ≈ 1.5~2 h；拟合受 --max-samples 控制。**用户已确认不关心本地训练成本**，如需加速：更小网络（d=64/4 层 ≈ 2~4 倍）、增大 workers、降低 data-sims-max；
- **ONNX 外部权重文件**：torch 2.14 导出会生成 `model-vN.onnx.data`（常量权重外部化），部署时 .onnx 与 .data 必须成对拷贝；
- 门限对局与验收对局使用同一批 eval-maps（用户提供）；验收图池为空时主循环跳过门限直接接受（带警告）；
- 样本体积 ~8KB/条，1000 局/轮 ≈ 8GB；主循环自动裁剪旧轮（保留 2 轮）。
