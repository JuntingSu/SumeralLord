# 数字领主 AI 训练 v2 · 阶段 4：验收

> **用途**：阶段 4 产物说明——v2 训练 AI 对 v1 基准（MCTS v45 权重）的验收脚本与流程。
> **版本**：v0.1（2026-09-22）。
> **关联**：《数字领主-AI训练方案v2-整体框架.md》§8、《阶段0~3/5》文档。

---

## 1. 验收定义（决策定稿 §8）

| 项 | 值 |
|---|---|
| 基准 AI | v1 引擎（回合级 MCTS + 规则生成器）+ **v45 权重**（`v1/runs/weights/v45.json`） |
| v2 训练 AI | 原子 MCTS + Transformer，部署配置：**200 模拟 argmax**（可配） |
| 地图 | 验收图池（用户提供，`train/eval-maps/`，7 张） |
| 局数 | 200 局（可配），**先后手交替**（v2 交替坐 1/2 号） |
| 达标线 | **胜率 > 65%** |

## 2. 组件

- `lib/workerpool.ts`：worker 批处理池（自 train-v2.ts 抽取，主循环/验收共用）；
- `scripts/worker.ts`：新增 `accept` 任务——v2（原子 MCTS）vs v1（`@dl/train` 的 `planMctsTurn`）；
  - v1 引擎经 `@dl/train`（main → `v1/lib/online.ts`）调用，权重从 v45.json 注入 `initMctsWeights`；
  - **v1 线上 bot 语义**：v1 计划偶尔含非法意图（其已知特性）→ 丢弃被拒意图继续下一条；跨回合/计划耗尽 → 重新规划；
- `scripts/acceptance.ts`：验收主脚本——构造 200 局任务（交替座次）→ worker 并行 → 统计胜/平/负 → 胜率 → 达标判定（exit code 0/1）→ 报告落盘；
- `lib/driver.ts`：`GameStats` 新增 `rejectedIntents`（被拒意图明细，败因分析用）。

## 3. 用法

```bash
# 默认：当前对手池 current 模型 + v45 基准 + 200 局 + v2 200 模拟 + 全部核
npx tsx v2/scripts/acceptance.ts
# 指定模型/参数
npx tsx v2/scripts/acceptance.ts --model ../runs/weights/model-v3.onnx --games 200 --v2-sims 200 --workers 14
```

产物：
- `runs/acceptance.csv`：一行汇总（timestamp, model, baseline, games, wins, draws, losses, winrate, pass）
- `runs/acceptance-games-<ts>.csv`：逐局明细（jobId, mapId, v2Seat, outcome, steps, reason, rejects）

## 4. 验证结论（阶段 4 验收）

- 机制冒烟（6 局、v2=30 模拟）：随机种子模型 v0 vs v45 基准 → **0-6 落败**（未训练模型输给训练过的基准，符合预期）；胜率统计/达标判定/报告落盘/先后手交替全部工作；
- v1 基准的意图拒绝（~0.8 次/局）是其固有行为（计划偶含非法意图），按 v1 线上 bot 语义处理（丢弃继续），不影响公平性；
- v2 侧拒绝恒为 0（掩码↔reducer 对拍保证）；
- v2 43 测试 + v1 96 测试 + 全部 typecheck 全绿。

## 5. 已知工程注意项

- **耗时**：正式验收 200 局 × v2 200 模拟 ≈ 5 小时（14 workers、单局 13~27 min）——训练出候选权重后再跑；
- 验收图池与训练图池完全独立（泛化检验）；
- 基准 v1 引擎的 `timeBudgetMs=5000` 兜底（同线上配置语义）。
