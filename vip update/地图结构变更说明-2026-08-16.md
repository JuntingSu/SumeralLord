# 地图码结构变更说明

> **修改日期：2026-08-16**
> **变更范围**：地图 JSON 文件格式、共享类型、后端加载/校验、房间势力映射、前端地图渲染、示例地图与生成脚本
> **参照规范**：`backend/static/maps/example.json`（带 `//` 注释的规范示例，可直接被加载器读取）

---

## 1. 为什么要变

旧地图格式（camelCase、`terrain` 平铺数组）只描述地形，不描述地块归属与兵力，也没有王城（出生首都）概念，出生点只能以 `forces[].spawn` 的形式挂在势力定义上。新格式对齐 `example.json` 规范，把"地面上发生了什么"完整表达为每个地块的三元组，为后续对局引擎（占领、驻军、中立势力"休闲"/"野生"）打好数据基础。

## 2. 字段对照（旧 → 新）

| 旧字段 | 新字段 | 说明 |
|---|---|---|
| `id` | （删除） | 地图 id 改由**文件名**派生（去掉 `.json` 后缀） |
| `columns` / `rows` | `column` / `row` | 列数 / 行数 |
| `randomSpawn` | `random_spawn` | 随机出生开关 |
| `cycleMap` | `cylindrical_map` | 圆柱地图（左右穿越）开关 |
| `fogMode` | `fog_mode` | 迷雾开关 |
| `starMode` | （删除） | 新规范中不存在 |
| `playerNum` | `player_num` | 玩家数，必须等于 `player_list` 长度 |
| `forces: [{seat, team, name, flag, spawn}]` | `player_list: [{name, team, computer, seat, flag}]` | **spawn 字段移除**，出生点改由 battlefield 王城地块表达；新增 `computer`（AI 难度 {1,2,3,255}，首版忽略，示例图填 255） |
| `terrain: number[]` | `battlefield: [[地形, 归属, 兵力], ...]` | 每地块三元组，见下节 |
| — | `timestamp` | 新增，`"YYYY-MM-DD HH:mm:ss.f"` 格式字符串，保持此形式 |
| — | `online_time_settings` | 新增，`{ total_time, round_time, time_bonus }`（示例图默认 600/60/0） |

## 3. 地形编码变化（重要）

| 地形 | 旧值 | 新值 |
|---|---|---|
| 平原 | 2 | **0** |
| 据点（城市） | 1 | 1 |
| 王城（出生首都） | （无此概念） | **2** |
| 海洋 | 3 | 3 |
| 山地 | 4 | 4 |
| 虚空 | 5 | 5 |

注意旧格式里 `2` 是平原、新格式里 `2` 是王城——直接搬运数值会出错，必须按上表重映射。

## 4. battlefield 三元组语义

- **归属（belongs）**：`1..player_num` 对应 `player_list` 中的 seat；`128` 无主地块；`255` 特殊中立玩家「休闲」；`0` 特殊中立玩家「野生」。
- **兵力（strength）**：该地块初始驻军数（旧格式无此数据，迁移时无主地块填 0）。
- **王城**：`terrain=2` 且 `belongs=seat` 的地块即该势力出生点。旧地图的 `forces[].spawn` 迁移时被转换为 `[2, seat, 1]`。
- 数组顺序不变：index 0 = 左下，从左到右、从下到上；长度恒等于 `row × column`。

## 5. 加载器行为变化

- 支持带 `//` 注释的 JSONC 地图文件（字符串内的 `//` 不受影响），`example.json` 本身即可作为第 4 张可玩地图加载（id 为 `example`）。
- 地图 id 由文件名派生，文件内不再需要 `id` 字段。
- 校验规则：三元组结构完整性、地形值 0~5、归属取值合法、seat 唯一且 1~127、`player_num === player_list.length`、`battlefield.length === row * column`。

## 6. 受影响的代码

| 文件 | 变更 |
|---|---|
| `packages/shared/src/types.ts` | `MapFullData`/`MapPlayer`/`BattlefieldTile` 重写；新增 `TERRAIN`、`TILE_OWNER` 常量 |
| `backend/src/maps/catalog.ts` | JSONC 注释剥离、文件名作 id、新格式校验 |
| `backend/src/api/maps.ts` | preview 响应改为 `{ row, column, battlefield }` |
| `backend/src/room/manager.ts` | 房间 forces 从 `player_list` 映射（房间 API 的 `RoomData.forces` 结构不变） |
| `frontend/src/components/HexMapPreview.tsx` | 改收 `battlefield`，王城地块自动标记所属座次颜色；地形色板适配新编码 |
| `frontend/src/pages/Maps.tsx`、`CreateRoom.tsx` | 字段引用更新为 snake_case |
| `backend/scripts/gen-maps.mjs` | 生成器改为输出新格式（保持确定性生成，重新生成结果与迁移结果一致） |
| `backend/static/maps/*.json` | 三张示例地图已按新格式重写 |
| `backend/tests/maps.test.ts` | 新增王城归属、三元组合法性、JSONC 加载用例 |

对局相关接口（`GAME_START.spawnAssignments`）中的 `spawnIndex` 语义同步明确为"指向该 seat 的王城地块"。

## 7. 迁移与验证

- 三张示例地图由脚本一次性转换，并经 `gen:maps` 重新生成比对，除 `timestamp` 外内容一致；王城位置与旧出生点完全对应（如 `map_duo_plain` 的 11/58）。
- 验证结果：后端 47/47 测试通过；前后端 `tsc --noEmit` 无错误；前端 vite 构建成功。
- 后续新地图请直接按 `example.json` 格式制作放入 `backend/static/maps/`，可带 `//` 注释。
