# POV 备忘：对局展示与结算口径（2026-08-25 用户决策）

> 背景：用户在 pov 分支上拍板四项与对局展示、结算口径相关的改动。涉及与既有文档冲突处，以本备忘为准并已回改文档。

## 决策 1：不计入对局数则不结算积分

- 若对局**不计入对局数**（回放步数 ≤ 25），则该对局**同时不结算积分变化**（score、wins 均不动）。
- 与既有口径的对齐：原"积分每局正常结束都结算（与步数无关）"作废；现在对局数、积分、胜场三者口径统一——只统计"计入对局数的对局"。
- 平局（winners=[]）仍不结算积分（保持原口径），计入对局数时 matches +1。
- 实现：`backend/src/stats/settlement.ts` 的 `settleMatch`——`!matchCounted || winners.length === 0` → `score_changes = []`；新增 `users.wins` 维护（计入对局数的对局中，在线获胜方 wins +1）。
- 文档回改：《数字领主-积分统计与排行榜设计方案.md》§规则口径 / §1.1 触发 / §1.2 说明 / §3.1.2 / §3.4 / §6.2。

## 决策 2：房间"玩家"列表显示积分与胜率

- 房间页左侧"玩家"列表，为每个玩家显示 **当前积分** 与 **胜率**（胜局数/对局数；对局数为 0 时显示 `—`）。
- 数据来源：`RoomPlayer` 新增 `score / wins / matches` 三字段（`users` 表实时读，序列化房间数据时注入）。
- 实现：`RoomManager` 新增 `statsOf` 注入（`backend/src/app.ts` 接 DB 读取）；`frontend/src/pages/Room.tsx` 玩家行展示 `{score.toFixed(1)} 分 · 胜率 {wins}/{matches}`（无对局数显示 `—`）。

## 决策 3：对局左侧势力列表显示扮演玩家名

- 对局页左侧势力列表中，势力名后用 `（）` 展示**扮演该势力的玩家名**；属于自己的势力仍显示 `（我）`（形式不变）。
- AI 势力仍显示 `AI（休闲）`，无主势力显示 `—`（第二行信息保留）。
- 实现：`frontend/src/pages/Game.tsx`；刷新/直连对局页时额外拉取房间信息以获取玩家用户名。

## 决策 4：我方回合/阶段开始居中提示

- 对局中，以下三个时机在**屏幕正中间**以**黑底白框白字**浮动展示对应文本，展示 **0.7s** 后**淡出**消失：
  - 我方回合开始 → `你的回合`
  - 行动阶段开始（我方）→ `行动阶段`
  - 加点阶段开始（我方）→ `加点阶段`
- 实现：`frontend/src/stores/game.ts` 从事件链（`END_TURN` 到己座 / `SWITCH_PHASE` 切到 ACTION、ADD_POINT）实时收集提示队列（**重连重放不触发**）；`frontend/src/pages/Game.tsx` 消费队列依次播放（0.7s 展示 + 0.3s 淡出）。

## 决策 5：结算页展示用户名与全员积分变动

- 对局结束后（VICTORY），结算弹窗（`Result.tsx`）中**所有玩家 id 改为展示用户名**，并**附带所有人的积分变化情况**（新增「积分」列：`+X.X` 绿 / `-X.X` 红 / 无变动 `—`）。
- 数据源：新增 `GET /api/game/:gameId/result`（`match_history` 行：玩家名 + `scoreChanges`；中止局无行 → 404）。
- 实现：`backend/src/api/game.ts` 新增接口；`frontend/src/api/game.ts` 新增 `fetchGameResult`；`Game.tsx` 于 GAME_OVER 后拉取并传给 `Result.tsx`（房间玩家名作兜底）。
- 文档回改：《数字领主-积分统计与排行榜设计方案.md》§3.4（原"不在结算弹窗展示积分变动"作废）、新增 §4.6。
