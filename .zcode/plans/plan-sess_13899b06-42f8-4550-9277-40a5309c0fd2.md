## 问题定位

**根因**（已亲自核实代码，非猜测）：对局棋盘在 `frontend/src/components/BoardCanvas.tsx` 中由同一容器内两层 `position:absolute; inset:0; width/height:100%` 的 canvas 叠加渲染——静态层画地块（dirty 重绘）、动态层画兵（每帧 rAF），两层共用 `canvasSize`（容器 CSS 尺寸 + DPR）。

- 静态层位图尺寸**无条件**重置宽高：`BoardCanvas.tsx:282-283`
- 动态层（兵层）位图尺寸守卫**只判断宽度**：`BoardCanvas.tsx:417-420`（引入自 cee88605，静态层在 cc17124 已修复，兵层被遗漏）

**触发链路**：移动端竖屏进入对局后，容器「高度变化、宽度不变」（浏览器地址栏收起/浏览器 UI 出现/首帧后 flex 布局定型）→ `canvasSize` 更新 → 静态层按新高度正确重绘；兵层因宽度未变跳过位图重置，旧位图被 CSS 按 100% 高度**非等比纵向拉伸**，而绘图代码已按新 `cssH` 计算几何 → 兵与地块垂直错位。此后每帧守卫都通过、错误持续，直到宽度变化或刷新——与「首次进入错位、刷新一次后恢复」完全吻合；且只在挂载后容器高度发生过变化的设备出现，对应「部分设备」。

## 修复方案（单文件改动：frontend/src/components/BoardCanvas.tsx）

1. **核心修复**：把 417-420 的守卫改为「宽或高任一不匹配即同时重置」：
   ```ts
   const bw = Math.round(cssW * dpr);
   const bh = Math.round(cssH * dpr);
   if (canvas.width !== bw || canvas.height !== bh) {
     canvas.width = bw;
     canvas.height = bh;
   }
   ```
   保留判定而非无条件重置，避免每帧重复清空/重分配位图（该层每帧都跑 rAF）。

2. **加固 A**：196-197 的 DPR 监听 `mq.addEventListener?.('change', update)` 对旧 iOS Safari（<14）/部分 WebView 静默失效，补 `mq.addListener` 兜底（清理函数 199-204 对称处理）。

3. **加固 B**：在 useLayoutEffect 中补充 `window.addEventListener('orientationchange', update)`（含 cleanup），覆盖个别 WebView 旋转/浏览器 UI 变化时不触发 ResizeObserver 的路径。
