## 目标

依据《数字领主-积分统计与排行榜设计方案.md》在新建 `score` 分支（**从 `master` 创建**，注意主分支是 master）上实现：积分系统（0 和制结算 + 获胜者保底）、个人数据统计（对局数 + 当前积分并入「我的战绩」页）、回放列表每局积分变动徽标、积分/对局数双榜排行榜页。

## 1. 分支与文档

- `git checkout -b score master`；将根目录未跟踪的《数字领主-积分统计与排行榜设计方案.md》提交到 score 分支作为功能规格。

## 2. 后端数据模型（双处同步 + 守卫迁移）

**`backend/src/db/schema.ts`**（Drizzle）：
- `users` 增加 `score: real('score').notNull().default(100)`
- `matchHistory` 增加 `scoreChanges: text('score_changes').notNull().default('[]')`

**`backend/src/db/client.ts`**（原生 DDL + 守卫迁移）：
- 两表 CREATE TABLE 内同步加列：`score REAL NOT NULL DEFAULT 100`、`score_changes TEXT NOT NULL DEFAULT '[]'`
- `openDb()` 的 `exec` 之后新增 `ensureColumn()` 守卫：`PRAGMA table_info` 查列缺失则 `ALTER TABLE ... ADD COLUMN ...`（存量库自动回填 100 分 / `[]`）

**`packages/shared/src/types.ts`**：
- `UserPublic` 加 `score: number`
- 新增 `ScoreChangeEntry { playerId, result:'win'|'lose', offline, oldScore, delta, newScore }`、`LeaderboardEntry { id, username, flag, score, matches, rank }`、`LeaderboardResult { list, me }`
- `MatchRecord` 加 `scoreChanges: ScoreChangeEntry[]`

**`backend/src/api/auth.ts`**：`toUserPublic` 补 `score: row.score` 并导出（供 users.ts 复用）；注册/登录响应即含最新积分（注册依赖列默认 100，不改插入逻辑）。

## 3. 结算核心

**`backend/src/game/manager.ts`**：新增 `countReplaySteps(game: Game): number` —— 读 `game.logFile` JSONL，统计 `type === 'INTENT_BROADCAST'` 条数（与回放页「N 意图」口径一致）。

**新建 `backend/src/stats/settlement.ts`**，拆纯函数 + 编排两层：
- `round1(x) = Math.round(x*10)/10`；`computeScoreChanges(players: SettlePlayerInput[]): ScoreChange[]` 按设计 §3.1.1 实现：`S` 一次快照求和（`S<=0` 全员 delta=0 防除零）→ `pay = round1(-20*score/S)` → `W = {isWinner && !offline}`（W 空则视同平局全 0）→ `remaining = Σ 败方/离线获胜者 (-pay)` → 胜者按 `omega=1/(score+100)` 归一化分配并 **`delta = max(5, delta)` 保底** → 败者 `delta = pay` → `newScore = max(0, round1(old+delta))`
- `settleMatch(db, games, game, winners, winningTeam, finishedAt): SettlementResult`：取真人参战者（`playerId!==null && !isAI`，`offline=!p.connected`）→ 按 playerId 一次查询快照 `{id, score, matches}` → `winners.length===0` 平局则 `score_changes=[]` → `steps=countReplaySteps`、`matchCounted = steps>100` → `db.transaction` 内：`UPDATE match_history SET score_changes=? WHERE game_id=?` + 逐人 `UPDATE users SET score=?, matches=<快照 matches + (matchCounted?1:0)>`（绝对值写入，避免并发漂移）

**`backend/src/ws/gateway.ts`** `onConsensusConfirmed` VICTORY 分支：`recordMatchHistory` 之后、GAME_OVER 广播之前，加一行 `settleMatch(this.app.db, this.games, game, payload.winners, payload.winningTeam, finishedAt)`（finishedAt 复用同一 `Date.now()`）。中止局走 `onConsensusFatal` 不动。

## 4. 后端 API

**`backend/src/api/users.ts`**：
- 新增 `GET /api/users/me` → `{ user: UserPublic }`（查本人最新行，含 score/matches）
- 扩展 `GET /api/users/:id/history`：每行 `MatchRecord` 补 `scoreChanges`（`JSON.parse(r.score_changes ?? '[]')`）

**新建 `backend/src/api/leaderboard.ts`**：`GET /api/leaderboard/:type`（type∈'score'|'matches'，非法 400 `INVALID_PARAMS`）—— 榜单 `ORDER BY <列> DESC, id ASC LIMIT 100` 逐行 rank 1..100；`me` 在榜直接取，否则 `rank = COUNT(严格大于本人)+1`（Drizzle `count()`+`gt()` 子查询）；挂 `authPreHandler`。

**`backend/src/app.ts`**：`await app.register(leaderboardRoutes)`（参照 userRoutes）。
